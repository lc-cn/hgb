# 阴阳师自动化项目调研

调研日期：2026-11-15。工作目录原为空目录，非 Git 仓库；本次只新增笔记。资料来自项目 README、issue 与发布页，未运行任何项目或游戏。网页抓取含缓存，不能据此保证 issue 状态或发布版本实时准确。

## 已确认需求

- 用户有可全天专用的 Windows，Android 也可接受。
- 目标覆盖游戏任务与活动，用户按需启用，并希望应对游戏更新。
- 用户进一步希望尽量自主理解新活动，减少人工适配。
- 尚未决定具体执行技术、恢复策略、资源预算及更新机制。

## 候选与证据

### OnmyojiAutoScript（OAS）

功能目录覆盖日常、每周、阴阳寮、副本及限时活动；采用 Python 后端、独立 GUI，许可证 GPL-3.0。这说明已有大量游戏任务实现值得评估，但 README 的功能列表不能证明每项在当前游戏版本都稳定。[项目 README](https://github.com/nearaura/OnmyojiAutoScript)

当前备份 README 自述：2026-11-08 原 runhey 账号受到 GitHub 限制，申诉期间使用 nearaura 备份。该说明是项目方陈述，不独立验证限制原因。部分原始 issue 当前仍可从抓取资料读到，另有页面返回 404；长期更新应考虑上游入口变化。[备份 README](https://github.com/nearaura/OnmyojiAutoScript#临时仓库)

- **登录与任务恢复：** [#1665](https://github.com/runhey/OnmyojiAutoScript/issues/1665) 报告游戏停在登录界面时，非 Restart 任务导航重复到超时。报告内对页面图孤立节点的因果解释由提问者借助 Claude 提供，未在本调研中通过源码或运行复现确认。它能证明存在这一历史报告，不能证明当前版本仍有同一缺陷。
- **错误完成判定与重复消耗：** [#1562](https://github.com/runhey/OnmyojiAutoScript/issues/1562) 报告新版悬赏界面下任务提前结束、协作重复执行。讨论指出退出秘闻后界面识别时序问题；有贡献者修改退出逻辑，用户随后反馈两天未遇到该问题，但同一串另有用户继续报告重复刷取。因此不能把整个 issue 简化成全部未修或全部已修。
- **皮肤变化与修复验证：** [#1708](https://github.com/runhey/OnmyojiAutoScript/issues/1708) 报告到期结界卡未收取却判为使用中，日志显示重复调度。维护者指出鲤鱼旗皮肤可能影响点击位置，附修复提交并标记“已修复等待反馈”；报告者随后说更换皮肤后恢复，但原皮肤更新后仍有问题。说明补丁存在不等于所有界面组合已验证。

### MaaYYs

项目由 MaaFramework、MXU 和 Go agent 组成，主要面向模拟器，提供 Windows 成品包。任务以 tasks JSON 与资源 pipeline 为准。README 明确列出任务起始界面、分辨率、渠道、皮肤、OCR 及游戏更新导致识别卡住的可能性；因此底层框架可复用，但不自动解决游戏流程维护。[仓库与 README](https://github.com/TanyaShue/MaaYYs)

- **功能覆盖存在具体边界：** [#99](https://github.com/TanyaShue/MaaYYs/issues/99) 请求司机邀请、打手接受、阵容切换等自动御魂组队能力；维护者于 2026-08-04 回复当时暂无支持计划。该历史回复不等于今天所有组队功能均不存在，需以当前任务配置复核。
- **长时运行与流程卡住的报告线索：** [#92](https://github.com/TanyaShue/MaaYYs/issues/92) 标题为运行一段时间后卡顿；issue 列表另列 [#127](https://github.com/TanyaShue/MaaYYs/issues/127) 准备页面卡住、[#128](https://github.com/TanyaShue/MaaYYs/issues/128) 结界和寮突破反复重打。本次未完整取得这些 issue 的正文和维护者回复，不据标题推断根因或修复状态。[issue 列表](https://github.com/TanyaShue/MaaYYs/issues)
- **维护在持续发生：** 发布页的 v4.0.4、v4.0.5 beta 记录了装备御魂误点、装备未成功、启动进入游戏等修复。这里只说明发布记录存在，不宣称它们是今日最新版本。[发布页](https://github.com/TanyaShue/MaaYYs/releases)

### Android 原生脚本候选

[assttyys_autojs](https://github.com/zzliux/assttyys_autojs) 基于 Auto.js Pro，README 列出多个副本与日常，并明确指出开发分辨率为 720×1280，其他分辨率未充分测试、异型屏兼容有限，建议虚拟机或云手机。仅核对 README，未全面评估其 issue、当前维护状态及运行依赖。

## 对设计的启示（提案，未实施）

1. 优先评估 Windows 专用机加安卓模拟器：与已存在资源的使用场景吻合，但最终需要在目标设备验证截图、输入、连接及连续运行。
2. 分开衡量功能覆盖与无人值守可靠性；功能存在不等于掉线、重启、更新后能继续执行。
3. 任务完成、识别失败、未知界面和等待其他玩家应是不同结果，避免把识别失败当作任务完成或把协作等待当作继续刷取。
4. “应对更新”需要区分素材微调、流程变化与全新玩法；当前证据不能支持无需维护即可自动理解所有新活动的承诺。
5. 可复用引擎与现有任务实现，但需另做源码、许可、可维护性和目标设备验证，再决定扩展既有项目还是新建应用。
6. 当前 issue 与 README 证据不能证明 AI 能自主适应新活动。视觉 Agent 结合可验证技能可作为待验证方案，需用从未写过流程的新活动评估理解、操作与完成判定，不能承诺零适配。

本次未决定或启用通知、自动重试、无人审批更新、资源购买、账号操作等行为，也未做部署或生产验证。
