> 本页记录旧版 30 页原型。最新完整重出稿为 [App v2](app-v2.html)，入口与验证见[本轮交付索引](../design/README.md)。下文旧布局未通过用户评审，仅作范围和流程追踪。

[打开低保真交互原型](index.html)。浏览器直接打开即可，无需安装依赖或启动项目；如浏览器禁止本地页面脚本，可在仓库目录运行 `python3 -m http.server 8765`，再访问 `http://localhost:8765/docs/prototype/index.html`。

本原型固定页面信息归属、导航关系与关键状态，供后续 UI 设计对齐。全部数据为演示，所有操作仅在内存中模拟，刷新即重置；不操作游戏、不保存凭据、不发起模型或通知网络请求。示例时间、数量、商品、渠道与阈值均不是产品默认值。

评审状态：用户认为现有横竖屏和悬浮球像网页嵌入 App，具体排版与视觉未通过。本目录保留需求覆盖和流程资料；正式 UI 不照搬这些卡片与浮窗，先验证新的原生交互方向。

## 一 查看方式

- 交互预览：左侧选择页面，手机内可点击主导航、业务列表、配置入口与关键操作；右侧说明页面用途及交接约束。
- 使用顶部“竖屏 App／横屏 App”切换主助手布局，横屏重新安排侧导航、列表和表单。可用 `?orientation=landscape#home` 直接预览；该布局与横屏悬浮球不同。
- 页面总览：按组查看全部原型图。每个页面有固定编号和 ID，便于 UI、技术与架构文档交叉引用。
- 悬浮球：从工作台进入游戏示意，点击展开、拖动移位；暂停和停止演示请求中到确认生效。临时隐藏不改变运行状态，可从页面目录再次打开。
- 细节表单：作为布局和字段示意，未接入真正的数据校验或存储；“保存”提示为模拟，不表示生产规则已实现。

## 四 后续 UI 需要保留的约束

1. 五个主导航、六类业务和具体任务归属保持一致；周期与模型依赖作为标签。
2. 单次执行、加入计划和长期托管开关是不同操作；计划引用任务规则。
3. 御魂副本与已有御魂管理分开；强化与整理分开，资源和保留规则可检查。
4. 任务结果、会话运行状态、能力状态和待处理问题分别呈现；停止后仍可能有未知结果。
5. 暂停／停止点击后先呈现请求中，不能仅凭点击宣布控制成功。
6. 通知已接收、用户已读、问题已处理和任务已恢复分别表达。
7. 截图、输入、悬浮和本机通知能力独立检查；本机提醒不可用不一概等同无法执行游戏。
8. 收起／展开／隐藏悬浮球不改变任务；复杂规则回主 App 编辑。
9. 权限失效示意不代表失去权限后仍能显示悬浮层；横屏图中的虚线面板是回退说明。
10. 本地支持和模型增强范围分开，不能将关闭模型变成整个 App 不可用。
11. 主 App 横屏保留同样页面与任务配置，从横屏游戏返回时不要求旋转设备；横竖屏转换不能丢失运行状态、配置草稿和页面上下文。原型表单尚未实现草稿保存，正式 UI 必须补齐该行为。

## 五 本轮验证与限制

已在独立临时配置的无头 Chrome 中核对 30 个页面渲染，未发现运行时异常或页面内容横向溢出。关键交互已检查：暂停请求与确认、模型开关、消息视图切换、模拟通知测试、悬浮球展开、停止请求与确认、停止后未知结果仍保留。原型图由同一 HTML 导出。横屏新增后，另核对 30 个页面的横屏访问和方向保留，以及悬浮球拖动不误触展开。

尚未实现完整任务条目选择、真实表单校验、计划编排、配置生效版本、全部状态组合与真实系统授权。原型中的运行反馈使用演示计时，不代表真实任务取消或恢复时限。网页尺寸不等于 Android dp，后续须真机及模拟器验证文字、触控、横竖屏和系统生命周期。

不将此 HTML 直接转为生产执行程序。正式 UI 按[UI 设计方案](../design/ui-design.md)补齐状态、表单、对象选择与平台行为；运行契约参考[系统架构](../design/system-architecture.md)和[技术方案](../design/technical-plan.md)。
