# 被动触发机制提案（2026-11-18）

状态：规则已由用户确认（第 6 节），尚未实现。

现在的任务都是“用户或计划发起”。协作邀请、组队邀请是游戏主动弹出的，需要一套“事件来了再处理”的机制。

## 1. 三个项目怎么做

| 项目 | 做法 | 问题 |
| --- | --- | --- |
| assttyys | 功能 3“悬赏协作”可选关闭、接受、拒绝和“仅接受勾协”；功能 4 接受组队邀请 | 要逐个方案勾选才生效；靠固定坐标取色 |
| OAS | 每次截图时检查邀请（`_burst`），支持接受、拒绝、仅勾协、勾协加粮协、忽略；接受后立即安排悬赏任务 | 默认全部接受；点击循环没有次数上限；只有任务运行时才检查 |
| MaaYYs | 只有主动执行的悬赏任务 | 没有被动处理 |

值得借鉴的是 OAS 的“截图时顺带检查”和“接受后追加悬赏任务”。三个项目都没有在空闲时持续监听。

## 2. 机制

新增**被动规则**：任务包声明“识别什么、怎么判断、做什么”，用户在设置里决定是否启用。

1. **发现**：任务运行时复用已有截图，不增加截图次数。没有任务时，只有用户开启“待命”且游戏在前台，才低频检查邀请区域。
2. **判断**：读取邀请内容，识别协作类型（组队也是协作的一种，并细分具体玩法）；识别不出的归为无法判断。
3. **响应**：类型在用户勾选范围内、且满足该类型的下级配置才接受，其余一律忽略。
4. **后续**：接受后按普通任务提交给执行器，例如接受勾协后追加悬赏任务。

## 3. 必须遵守的规则

- **唯一执行器不变**：被动处理也是一次高优先级运行，在当前输入安全静默后抢占，处理完恢复原任务。
- **看不准就不点**：无法判断类型时不接受，记录并通知用户。
- **点击后要核对**：确认弹窗消失，最多尝试 3 次，失败时结果记为未知。
- **消耗有上限**：会消耗资源的类型要受下级配置里的上限约束，到达后退出队伍，不再接受该类型。
- **账号隔离**：规则按账号保存，换号后不沿用。
- **全程留痕**：每次邀请的类型、决定和结果都写入运行记录。
- **好友信息只留在本机**：白名单只保存好友昵称文字，不保存截图，不上传。

## 4. 分三期

| 期 | 内容 | 前置条件 |
| --- | --- | --- |
| 一 | 任务运行时按勾选的类型处理协作邀请，接受后追加悬赏 | 真机采集协作弹窗样本，补全局弹窗守卫（路线图 G 项） |
| 二 | 待命监听：没有任务时也能处理协作邀请 | 第一期稳定；测量耗电和发热 |
| 三 | 组队类型及其下级配置：好友范围、接受、准备、战斗、结算、到达上限或队长退出后离队 | 通用战斗循环；好友列表和邀请人昵称的识别 |

## 5. 风险

- 协作邀请有时限，抢占要足够快，具体时限需实测。
- 战斗中弹出邀请时，点击可能影响战斗，第一期先只在非战斗画面响应，战斗中是否响应实测后再定。
- 组队会消耗体力，也会影响队友，出错成本比单人任务高，所以放在最后一期。

## 6. 用户已确认的规则（2026-11-18）

| 编号 | 规则 |
| --- | --- |
| P1 | **接受的协作类型**：一个多选项，列出所有协作类型，组队按具体玩法分别列出，默认都不选。都不选就是不处理邀请，没选中的类型一律忽略 |
| P2 | **下级配置**：勾选某个类型后，才展开这个类型自己的配置，例如好友范围、次数上限、体力上限 |
| P3 | **待命监听**：提供开关，默认关闭 |

### 配置结构

```text
接受的协作（多选，默认都不选）
├─ □ 勾玉协作
├─ □ 猫粮协作
├─ □ 狗粮协作
├─ □ 活动邀约
├─ □ 御魂组队
│    └─ 勾选后展开：好友范围、次数上限、体力上限
├─ □ 探索组队
│    └─ 勾选后展开：好友范围、次数上限、体力上限
└─ □ 其他组队玩法（按真机样本补充）
```

- 选项和下级配置都由任务包声明，游戏新增类型时更新任务包即可，不用升级 App。
- 上表的类型来自参考项目，完整列表要用真机样本核对后再定。没有列入选项的类型不会被接受。
- 会消耗资源的类型，下级配置的上限必须填好才能保存，不提供隐含的无上限。
- 任务配置需要新增“字段按某个选项是否选中来显示”的能力。隐藏字段不参与校验，已填的值保留。

### 选择好友

好友范围是组队类型的下级配置，默认为空，可以选择具体的某个好友：

1. 用户点“读取好友列表”，助手进入游戏好友页读取昵称，读完回到原画面。这是一次普通任务，要排队执行。
2. 收到过的组队邀请，邀请人也会出现在可选列表里。
3. 收到邀请时，邀请人昵称必须和所选好友完全一致才接受；识别不确定时不接受，并通知用户。
