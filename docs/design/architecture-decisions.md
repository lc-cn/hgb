# 架构选择提案

版本：1.0-draft；日期：2026-11-15。对应[系统架构评审稿](system-architecture.md)。技术选择待评审，不是已批准实施清单。

具体技术栈、候选比较及成立条件以[技术方案1.0](technical-plan.md)统一汇总。基础组件已有明确推荐；OCR／平台适配的实验门槛不等于所有技术均未选择，研究报告里的局部优先级也不直接替代最终集成取舍。

## 已确认的核心，不作为技术选项反复讨论

内容层次为Action基础能力→Step动作编排→Task步骤＋配置schema→Plan任务集合＋时间。Executor是唯一执行控制，包含队列、当前任务和pause/resume(mode)，不在各内容层另建暂停／恢复状态机。动作／步骤表达提案见[模型说明](action-step-task-model.md)。

`resume(continue)`跳过已完成步骤，未完成步骤从入口新观察。`resume(restart_current_task)`当前任务从step1，其他任务不变。恢复保持本轮包／规则、累计消费和真实事实；可能已生效但未知先核对，不盲重做。两种方式都经同一执行器排序，不另入一份计划。

## 推荐选择及替代

| 选择 | 推荐及原因 | 替代／取舍 | 冻结前证据 |
| --- | --- | --- | --- |
| App形态 | Android原生Kotlin＋Compose，本地模块化；直接处理授权、窗口与生命周期 | Flutter／WebView仍需平台桥，本项目没有跨平台UI要求；HTML只保留原型用途 | 原生横竖屏、浮层及生命周期实验 |
| 执行核心 | 一个Executor，TaskWorker只解释步骤并报结果；计划只定时提交集合 | 每任务／计划一套运行控制会重复暂停／恢复和调度，已被用户否定 | 同一个pause/resume(mode)入口覆盖所有页面与浮层 |
| 云任务 | 单个启用任务集＋受限步骤解释器，流程与素材独立于APK更新 | 仅更新模板表达力不足；任意JS／DEX／native插件扩大取消、权限与恢复复杂度；已有pipeline可比较但不能直接冻结依赖 | 日常、兑换、强化代表流程在同容器更新，新能力缺失明确不兼容 |
| 平台输入 | 标准能力先验证，独立薄DeviceBridge只管票据／输入／静默 | 同进程最简单，但不可中断native卡死时可能无法独立撤销；不引PC/ADB作为产品常驻依赖 | 真实卡死／迟到回调／桥断联，静默前无新输入 |
| 持久化 | Room／SQLite存进度与必要事实，私有文件存大资源；不用通用事件溯源 | 多JSON难保入队去重及步骤完成同提交；DB不能使手势／游戏／文件原子化 | 意图前后／输入前后／步骤结果提交点中断与数据迁移 |
| 识别 | 本地文字、图标、相对布局和步骤上下文；云视觉可选，只提案 | 单整页模板易随主题失效；全云依赖违反关闭模型仍可用要求；不提前冻结OCR优胜者 | 离线闭环、留出主题、关键数字和模型关闭测试 |
| 登录态 | 元数据与快照密文分开，同环境阶段日志、后备与fresh identity核对 | 昵称不能证明身份，某个token文件不能证明完整状态，Root不证明可恢复 | 同环境A→B→A、提交中断／不符／回退、会话失效 |
| 事件／通知 | 业务结果＋raw事实先提交，规则与投递独立消费和持久化 | 失败不能回滚结果或占住业务输入；发送中未知不自动重发 | 规则／投递写入失败与业务存储失败对照，真实渠道结果 |
| 代理与秘密 | 每请求域冻结已保存route，连接归属隔离秘密，Keystore保护密文 | 全局系统代理改变未选范围；一个HTTP客户端不证明SMTP代理；不直连fallback | 三域分别验证HTTP／SOCKS5、认证／DNS／TLS及SMTP |

模块划分是实现局部变化的接合处，不是一项功能一套框架或进程。只有DeviceBridge的独立进程具有明确卡死撤销理由；具体Android组件、OCR／网络库、版本和最低系统通过实验后冻结。

## 恢复设计明确删除的内容

不实现独立TaskRun／PlanRun的paused/resuming状态机、动作中途游标、多层checkpoint、资源预留快照和工作器上下文恢复。只保留步骤完成进度、最小尝试身份及副作用核对必要的actionId／输入代际／结果。不是把旧复杂恢复抽象换个名字保留下来。

## 仍待明确的事项

目标手机／模拟器和分发方式；任务源信任／撤回；日程时区、错过／前轮重叠、时长到限；新活动允许动作、费用／外发；停机期间错过的计划触发策略。这些不改变已确认的内容层次和唯一执行器，也不默认引入补做、自动重试、自动激活或跨服务fallback。

改变推荐时应说明触发证据、影响的数据／调用／恢复路径和必要验证。正式选型、依赖版本与实施需后续评审；当前没有编译、发布或实机成功证明。

## 2026-11-16 已确认补充

App 被系统杀掉再打开后，自动恢复可确认安全的任务；未知结果仍暂停核对。保留既有人工暂停。该决定不授权补做错过的定时计划、自动启动／重登游戏、自动重试未知副作用或变更任务版本。恢复能力仍按输入静默、目标／账号和步骤结果的实际证据实现。
