## 0. 数据结构原则：最少数据表达意图，重复的抽成引用

现状（2026-11-21 量 v1.1.0 草稿包，584 KB）：参考尺寸写了 781 遍、识别门槛 1766 遍；75 个区域写出 2581 次（“式神育成”标题区域 333 次）；109 个页面状态写出 701 次。原因是 Python 生成的是展开态，没有引用。

任务包与草稿都存**紧凑态**，App 读包时展开成引擎格式（引擎不变）：

| 层 | 内容 | 写法 |
| --- | --- | --- |
| 游戏定义库 | 有名字的区域、状态库、模板（资源）、干扰页、片段库 | `targets[].library`：`regions{名字: [x,y,w,h]}`、`states[]`、`interruptions[]`；`snippets[]` 按游戏归属 |
| 默认值 | 参考尺寸、文字门槛、模板门槛、等待 / 轮询 / 稳定时长、点击时长、识别配置 | `targets[].library.defaults`；动作没写的输入，按该动作合同声明的输入补默认值 |
| 引用 | 区域、状态、模板、片段都写名字 | `"within": "HALL_INFO"`、`"states": ["好友列表"]`、条件简写 `"有字": "寮信息@HALL_INFO"` |
| 守护 | 同一字面值（区域、条件、一段动作）出现第二次 | 编辑器提示“提取成区域 / 状态 / 片段”，一键替换所有出处 |

展开顺序：默认值 → 区域与状态引用 → 片段与逐项 → 干扰页组合节点；展开后才做引擎校验。校验问题的位置报回紧凑态（用节点 id），不报展开后的路径。


### 1.1 层次

| 层 | 是什么 | 任务包 JSON |
| --- | --- | --- |
| 游戏 | 目标应用、识别配置、参考尺寸、状态库、干扰页、账号识别 / 切换任务 | `targets[]` `visionProfiles[]` `states[]` `interruptions[]` |
| 任务 | 有序步骤 + 配置项（+ 被动触发） | `tasks[]` |
| 步骤 | 一段编排，完成依据，可带运行条件 | `{id, name, program[] \| use+with, when?}` |
| 片段 | 带参数、可声明产出的可复用编排 | `snippets[]`：`{id, params[], exports[], program[]}` |
| 动作 | App 能力 | `{"type":"action", id, ...}` |
| 编排 | 分支、重复直到、重复 N 次、逐项、退出 | `branch` `until` `repeat` `forEach` `exit` |

**所有节点和分支情况都有稳定 id**（编辑器生成），补丁、断点、编号、时间线都按 id 寻址；界面上的“2.4.1”只是显示用的位置编号。

### 1.2 两个时刻：读包时与运行时

| 读包时（编译期）确定 | 运行时确定 |
| --- | --- |
| 片段展开、参数代入 | 动作产出（找到的位置、读到的字和数字、页面状态） |
| `forEach` 逐项展开 | 分支走哪个情况、循环跑几轮、何时 `exit` |
| 状态库内联进等页面 | 配置快照里的值（运行开始时定） |
| 干扰页组合节点展开 | |

App 规定一部分输入必须由任务版本写死（区域偏移、拖动位移、等页面的状态、`requireNoText` 等），所以凡是要喂给这些输入的变化量，只能来自读包时：片段参数、`forEach` 表项；配置项不行（运行时才有）。

### 1.3 片段

- 参数有类型：文字、数字、开关、区域、模板 id、状态名；可给默认值。参数只接受编译期的值：常量、`forEach` 表项、外层片段参数。
- 表项和参数支持简单算式（`add` / `sub` / `mul`，如 `{"add":[438, {"mul":[202, i]}]}`），用于“第 i 张卡的 x = 基准 + i × 间距”；也可以直接在表里写算好的值。
- `exports`：片段声明哪些内部产出可被外面用（名字 → 内部动作产出），展开后由校验器按普通数据流规则检查。
- 展开时动作和节点 id 加片段实例前缀，禁止环。
- 引用方式两种：整步引用（`use + with`，替代现有 `routines`，发布前无兼容负担），以及**在程序任意位置内联引用**（`{"type":"snippet","use":id,"with":{...}}`）。两种都在切片 1。

### 1.4 页面状态库

- 每个游戏一个状态库：状态有 `id`（英文，任务包用）和名字（中文，界面用）；条件 = 有字 / 没字 / 有图 / 没图，各带区域与门槛；可基于另一个状态加减条件派生。
- **状态可带参数**（如“第 i 张卡满级”带区域 x），等页面引用时给参数，参数同样只接受编译期值。
- 等页面写候选状态（及参数）；读包时内联成 `awaitScreen.states`，引擎的 `awaitScreen` 不变。
- 互斥在同一个等页面的“候选 + 干扰页”集合内检查；样本标注“应是哪个状态”，判定台查冲突与漏判。

### 1.5 编排节点

| 节点 | 语义 |
| --- | --- |
| `branch` | 值来自产出 / 配置项 / 参数；情况：`equals` · `contains` · `atLeast` / `atMost` · `inRange` · `missing`（可选配置未填）· `otherwise`；比较值可为常量、配置项、另一个产出。无情况匹配且无 `otherwise` → 步骤“结果未确认”。配置分支按控件定类型（开关 / 数字 / 单选 / 多选），不再限必填单选 |
| `until` | 值来自循环体的产出；增加“任一条件成立”（布尔或）；最后一轮的顶层产出带出循环 |
| `repeat` | 次数来自常量 / 配置项 / 参数 |
| `forEach` | 遍历写死的表；**读包时展开**成一个有 id 的顺序块，内含 N 份副本，每份的节点 id 加表项前缀（`row#2.xxx`），表项代入；校验器按顺序逐份推进数据流，不用重入抽象；可被 `exit` 截断。表中各项字段与类型必须一致 |
| `exit` | `exit: 循环 id`，结束指定的那层循环（可跨多层），记为正常结束 |

**循环出口产出**：每个有 id 的循环块（逐项、重复直到、重复 N 次）产出 `exited`（是否被 exit 结束）和 `exitIndex`（退出时在第几份，从 0 起；没退出为 -1）。表是写死的，第几份就确定了是哪一项，编辑器显示为对应表项。循环体里的产出不带出循环，需要时在循环后重新看画面。片段是封闭的：片段里的 exit 只能退出片段内部的循环。分支后可以按 `exited` 区分“找到了”和“全跑完没找到”。

**校验与运行**：
- 校验器把每个 `exit` 点的数据流并入循环出口：已核对集合取并，产出新鲜度取交；块内产生的句柄只有经 `exports` / 循环出口产出声明的才能在块外用。
- 运行时 `executeBlock` 返回密封结果：正常结束 / 退出某循环 / 步骤结果。可能被 `exit` 截断的循环里，任何动作都不视为“步骤最后一个动作”，完成依据只看循环后的核对。

### 1.6 干扰页（执行器层组合节点）

- 游戏层声明干扰页：状态 + 处理片段 + 每次等页面最多处理次数。
- 每个“等页面”在**读包时展开成组合节点**：
  1. 等“候选状态 ∪ 干扰页状态”；
  2. 命中干扰页 → 跑展开后的处理片段（动作带前缀 id，各自记日志和回执）→ 回到 1；
  3. 命中候选 → 结束，产出与普通等页面相同；
  4. 处理次数超限 → 步骤“结果未确认”。
- 组合节点**保留原等页面的动作 id**，校验器把它当作一个 `awaitScreen` 动作：角色为核对、视为可能有输入——先作废之前的句柄，再登记它自己的新鲜产出（最后一次等页面的状态和观察），所以块外照常可用；`usesInput` 按展开后的内容计算。
- 互斥范围包括干扰页：候选状态与干扰页状态两两互斥，否则一帧同时命中会等到超时。
- 处理次数上限按**每个等页面组合节点**计（每个干扰页各自上限，默认 3），超限 → 结果未确认。
- 不在 `awaitScreen` 动作内部发输入。

### 1.7 恢复片段

- 步骤可指定恢复片段（如“回庭院”）。步骤停成“结果未确认”后：
  - 仅当本次尝试的输入已确认静默（Quiet）才允许；输入结果不明（Unconfirmed）时禁止。
  - 作为一次独立尝试运行，有自己的 ticket 和日志；恢复片段里不许出现确认、购买、领取类按钮（校验）。
  - 跑完仍交用户决定，不自动重试原步骤。

### 1.8 数据流规则（引擎已有，编辑器镜像）

产出只在同一步骤同一次尝试内有效；有输入的动作（含干扰页组合节点）之后旧观察、位置、区域失效；点击类出手前按原条件重新定位；每条路径结束前必须核对。

## 2. 配置项

### 2.1 定义 → 设置页

名称、说明、控件（决定值类型）、选项（显示 / 存的值）、单位范围步长、推荐值（点了才采用）、必填（条件字段为“显示时必填”）、分组分页、只在…时显示（父字段可为单选 / 多选包含 / 开关等于开）、只读。设置页由 App 与网页同一渲染器生成。

### 2.2 值的生命周期

按（游戏账号, 任务）存服务端 → 作业创建时拷入（必填缺或非法则不下发）→ 运行开始存快照，继续与重试都用它 → 试跑用测试值。

### 2.3 影响执行的五处

| # | 用在哪 | 编译成 | 运行时 |
| --- | --- | --- | --- |
| ① | 步骤运行条件 | 步骤 `when` | 不满足：整步不跑，记“已跳过（…）” |
| ② | 分支 | `branch` | 无匹配且无“其他”→ 结果未确认 |
| ③ | 动作输入 | `bindings: configuration` | 只用于允许运行时取值的输入（如找字的文字、阈值）；不能喂“必须写死”的输入 |
| ④ | 次数 / 上限 | `repeat` / `until` | 0 次不执行 |
| ⑤ | 被动触发 | `trigger.enabledBy` | 多选为空不触发 |

`when` 读配置快照，步骤重跑结果不变；`clock.now` 每次步骤重跑重新取值，跨零点继续可能走另一路，属预期。

### 2.4 条件字段守护

隐藏时无值；只能在父条件一定成立处读（运行条件即父条件，或在按父字段分支的对应情况里）；编辑器与引擎校验器都检查。

### 2.5 发布时的设置兼容

对比上个发布版本：新增必填、删改选项值、改控件、收窄范围 → 列出；启用后标“需补齐设置”。

## 3. 校验与编译只有一份

服务端用 `core/engine` 的同一 `BundleCodec` 提供 `POST /api/dev/check`（问题列表按节点 id、每个节点可用产出及失效原因、步骤入口 / 出口状态），网页 300 ms 去抖调用。动作目录随每个 App 版本上传服务端。编辑元数据发布时剥离。

## 5. 资源、样本与识别

- 样本：原图、设备、分辨率与宽高比、整屏识别结果、名称、标注状态；只属于作者。按宽高比分组；只有一种比例时提示。区域优先“相对锚点”。
- 模板：在样本上框选 → 服务端换算参考尺寸并裁图 → 作者命名，自动生成合法 assetName、sha256、大小 → 立即在同比例样本上算最高 / 次高分。裁框内有识别文字须逐个确认“是游戏界面文字”；与标为“玩家信息”的区域重叠则拒绝。
- 判定在哪算：切片 1–2 由在线手机执行（与真跑同一识别器）；没有在线手机时判定台显示“需要在线手机”，不做近似。切片 3 在服务端部署同版本识别器（MaaFramework，Linux arm64），验证与手机结果一致后再作为默认。

### 5.4 素材体积与识别效率

现状（v1.1.0 草稿包）：识别模型 det 9.9 MB + rec 21 MB 随每个任务版本重复上传；15 个模板共约 130 KB（单个 3–19 KB，最大 54×150）；JSON 528 KB。

- **模型不随任务版本走**：识别模型放在单独的“模型”发布里，任务包只按摘要引用；App 已按摘要缓存，模型不变就不下载也不上传。
- **发布只传新素材**：按 sha256 判断，旧版本已有的素材直接引用旧附件，不重复上传。
- **模板要小**：裁到最小可区分的图案，默认上限 64×64（超出要作者确认理由）；去掉多余背景；无损压缩、去元数据；同图（同摘要）自动去重，相似度 > 0.95 的两张提示合并。
- **必须配搜索区域**：模板和文字都在区域里找，不许整屏找（确需整屏要声明）；区域越小越快，判定台显示每个区域的面积。
- **等页面的代价可见**：检查接口按“模板数 × 区域面积 + 文字窗口面积”估算每次轮询耗时，超过 1 秒标黄，并建议先用模板排除（引擎已是先模板后文字）。
- **体积预算**：发布页显示任务包 JSON、模板总量、新增上传量；紧凑态 JSON 目标 < 100 KB。
- **引用旧附件**：资源写 `release`（所在版本标签）时 App 去那个版本下载；发布时同摘要同长度的素材自动改为引用，同图不同名各占一个附件。
- **旧 App 不被新包打断**：发布说明末行写 `min-app: x.y.z`，App 列出版本后跳过需要更新 App 的、取版本号最高的；该行无法解析视为不能运行。
- **不设为最新**：GitHub 的“最新版”留给不认识 `min-app` 的旧 App；引用了旧附件的版本不能设为最新。
- **样本先识别再裁**：手机上传样本后补识别文字和玩家信息区域，才能裁模板；发布时按当前的玩家信息区域再查一遍。

## 6. 草稿与协作

- 表：`drafts`（开发者 × 游戏）、`draft_patches`（节点 id + 操作 + 来源 + 时间）、`samples`、`debug_runs`。
- 按节点 id 合并补丁，只有同时改同一节点才冲突；手机数值微调 1 秒去抖。
- 资格：任务仓库写权限的 GitHub 账号；每请求校验（缓存 10 分钟）。

## 7. 手机端命令（复用作业通道，与托管作业互斥）

| 命令 | 内容 |
| --- | --- |
| 采样 | 截帧 + 整屏识别 → 样本 |
| 探测 | 对当前画面判定指定等页面的候选与干扰页；判断是否满足某步骤入口 |
| 判定 | 对选定样本用同一识别器判定状态（切片 1–2 的判定台） |
| 试跑 | 任务 / 某一步；切片 3 起可加断点 |

起点只能是步骤开头（调试时可选“从某节点起”：工作台合成一个临时步骤，开头补一个“等该节点的入口状态”）。
隐私：识别原文只在手机本机与作者样本里；`debug_runs` 上传的读文字产出只保留长度和是否匹配，不存原文；数字产出照常上传。

## 8. 步骤入口与出口

入口 = 第一个等页面的候选状态；出口 = 每条路径末尾核对的状态；由检查接口算出。相邻步骤（含被 `when` 跳过的情况）出口须属于后一步入口。

---

## 9. 游戏设置页

目标应用、识别配置、状态库入口、干扰页、账号识别（不得有配置项）与切换（只有必填“昵称”，找字文字绑配置——引擎需确认找字的 text 允许绑配置，不允许则在切片 2 放开）、片段库入口。
