# UI v3 独立质量验收清单

日期：2026-11-15。范围：本地可点击设计稿，不是 Android 实现验收。本清单只定义检查，不证明任何页面或能力已通过。初始状态全部为「待验证」；真实浏览器、截图与交互证据由根 agent 汇总。

## 判定与证据

- **M：已确认约定**。最新用户决定优先，随后为当前 PRD、领域与架构交接。旧 `app-v2.html` 只作流程参考；其中开放开发开关、旧 PlanRun 暂停状态、缺失重新开始入口均不是正确基线。
- **D：设计建议**。允许有同样简单、可用的替代，不以颜色偏好、固定列宽、建议阈值或未冻结 JSON 字段阻断。
- **B：交付边界**。模拟必须诚实，不能由页面存在推断真实授权、输入、账号恢复、通知、云发布或 24 小时运行已实现。
- **P1**：权限失守、核心操作不可达、功能整页缺失、业务控制／数据归属错误，或横竖屏无法完成核心流程。必须退回修正。
- **P2**：可复现的操作歧义、状态遗漏、重复控制、截断／遮挡、表单或导航退化。影响用户完成已确认流程时必须退回；纯风格意见不升级。
- 源码出现按钮、字符串或媒体查询只能证明「有表达」。通过还需真实浏览器操作后的可观察结果；无真实后端的状态只能标「本地模拟通过」。

证据记录建议：`检查 ID / 页面或 route / 初始夹具 / 操作 / 预期与实际 / 截图路径 / 结论`。缺陷必须给出复现入口和具体改法。横竖检查至少为 412×860 与 900×412；这两种尺寸不代表全部 Android 设备兼容。外置评审工具可切换模拟状态，但不得被误认成普通产品控制。

| E04 M | 用户暂停初衷；ARCH 暂停与两种恢复；INT 执行队列 | 当前项暂停、长按停止、仍有等待项 | 暂停与停止后全队保持人工暂停；停止取消当前本轮而非删除未来日程。长按不会再触发短按，取消手势不会误停止；只恢复明确选择的执行器。 |
| E05 M | 用户最新执行器确认；MODEL §4；ARCH §2 | 暂停后继续／重新开始，任务位于计划中 | 两种恢复入口可找到；继续重做未完成步骤，重新开始只从当前任务第一步；已完成步骤／计划成员符合各自语义。无另一个可独立暂停／恢复的 PlanRun；其他任务进度不被重置。 |
| E06 M | 用户队列移除确认；INT 执行队列 | 右滑当前、卡住、等待、挂起项 | 右滑可移除，另有可访问行操作；当前先「移除中」安全撤销再交接，不依赖卡住任务自己返回；非人工暂停时后续继续，原本暂停时不解除暂停。移除不抹除未知证据。 |
| E07 M | CTX 运行与结果；ARCH §5；INT 执行队列 | 已确认失败／结果未知／无后继 | 确认失败记录真实原因并继续；未知与失败分开，不盲目重放消费动作，不因读通知／改配置／删队列自动解决。无后继仍有可解释状态和结果。 |
| E08 M | 用户队列等待通知要求；PRD §6.1 | 长等待、人工暂停、规则设置 | 可从通知管理找到排队等待规则与时长配置；等待事件与渠道订阅区分，暂停等不适用时段不伪装成执行卡死。UI 不自行新增取消／重试或默认告警阈值。 |

## 必跑旅程与签收条件

根 agent 应以页面 manifest 检查缺页，再至少运行以下旅程；每条至少覆盖相关横竖屏，不能仅用截图证明操作正确：

1. 任务／计划列表星标、入队、防重复 → 工作台暂停 → 继续／重新开始 → 长按停止与右滑当前移除的不同队列结果；补充失败、未知、高优插队夹具。
2. 计划新建、指定一个星期、排序、非法时长／空任务提示、保存生效但不立刻入队；返回与旋转保留草稿。
3. 版本顶栏红点→极简版本行展开／收起→按钮不冒泡→启用旧版本／占用删除→拉取失败保持本地。
4. 模型预设配置／新增→渠道测试与保存分离→规则订阅事件→历史左右 tab→代理范围选择；至少各看一次失败与空态。
5. 工作台未启动／运行未保存／已保存→账号待核对／失败／成功与原队列、账号计划归属；三层悬浮过滤和暂停控制不消失。
6. GitHub 拒绝／未知直接路由保护→授权制作→有配置字段的任务→错误定位→草稿调试与恢复→一次上传失败／未知／成功；确认不丢其它任务、不自动启用。

签收前需有：页面清单与双方向截图索引、关键交互的实际浏览器结果、独立源码审查、已修问题的复测记录、剩余限制。未做真实 Android／Root／GitHub／云网络／游戏验证的能力单列为未验证，不能写成完成。P1 未清零不得交付通过；P2 按影响修正或明确剩余限制，不以总检查数掩盖核心缺口。
