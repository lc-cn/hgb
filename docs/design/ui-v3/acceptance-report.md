# UI v3 质量验收

日期：2026-11-15。结论：本轮高保真 UI 与本地可点击设计稿可交付评审；已发现的阻断及可用性问题均已修正并复测。此结论仅适用于设计模拟，不表示 Android 应用、游戏自动化或任何远端服务已实现。

## 交付入口与范围

- [设计总览与截图筛选](index.html)
- [主 App 可点击预览](app.html)：65 个初始页面，五个主入口，任务配置、计划、版本、通知、模型、网络、游戏账号及三层悬浮。
- [开发者可点击预览](developer.html)：14 个页面，受保护授权、表单制作、动作及引用、配置 schema、资源、JSON、调试、诊断与上传。
- [主 App 交接](main-design-notes.md)、[开发者交接](developer-design-notes.md)、[独立验收标准](quality-checklist.md)。

设备画板为竖屏 412×860、横屏 900×412。评审按钮和模拟边界说明均在设备框外。任务、账号、仓库、模型、版本及数值为夹具；占位仓库并非已创建或已授权的真实仓库。

## 打回与复测

| 编号 | 等级 | 发现的问题 | 修正及最终证据 |
| --- | --- | --- | --- |
| R01 | P1 | 停止当前项后，“继续队列”无法恢复等待项 | 无当前任务走原有安全恢复及核对；main-check 双方向停止→继续→出队通过 |
| R02 | P2 | 恢复展示夹具残留，可能截获新当前项的暂停 | 全部投影绑定 runId，换代清理；独立源码复查、主稿联调及额外恢复检查通过 |
| R03 | P2 | 恢复后文案为暂停，列表／悬浮仍显示播放图标 | 统一控制展示投影；extra-check 双方向三个入口检查通过 |
| R04 | P2 | 工作台用计划名压过当前任务名 | 当前任务为主文，计划名次文，总优先级保留；ux-results 与最终截图通过 |
| R05 | P2 | 暂停／移除等过渡态的控件禁用规则不一致 | 工作台、列表、悬浮共用控制状态；extra-check 过渡态检查通过 |
| R06 | P2 | 更新失败／不兼容只短暂提示，之后无法判断原因 | 列表上方保留按需短提示，版本行仍极简；main-check 离线入口通过 |
| R07 | P2 | 任务列表副文堆入详细影响说明 | 列表只留周期与优先级，详细说明保留在配置页；最终截图复查 |
| R08 | P2 | 横屏模型页未展开时右侧大幅空白，新增按钮掉行 | 未展开使用完整控制区域，展开后分栏；模型 47 项及截图通过 |
| R09 | P2 | 横屏工作台异常条和结果被挤成两个矮滚动窗 | 结果并入右侧滚区，左侧完整展示当前任务及短异常；extra-check 几何检查和截图通过 |
| R10 | P1 | 调试“重置”清除未知结果，绕过核对再次执行 | 按钮与命令双重阻断，保留证据；浏览器已复现原问题，dev-check 伪造命令反向检查通过 |
| R11 | P1 | 明确发布权限失效后重新授权仍无法上传 | 确认未发布的尝试可恢复编辑；在途撤权保持结果未知，不自动重发；dev-check 通过 |
| R12 | P2 | 试跑未校验实际配置值的必填／范围等约束 | 提交时验证，保留非法值并定位预览字段；dev-check 精确数值越界检查通过 |
| R13 | P1 | 旧诊断转入授权入口后，新受保护空间缺诊断页 | 增加只读观察、版本、输入归属及唯一执行器页；路由守卫和双方向页面检查通过 |
| R14 | P2 | 同名字段显示另一任务的遗留校验错误 | 值与错误均按任务归属；独立复查及 dev-check 跨任务检查通过 |

另经作者自审固定了调试任务／参数快照及上传的完整任务集快照；浏览器检查验证后续修改草稿不会偷换在途内容。审查期间发现的“成功后不能发下一版”和“测试值串任务”属于并发读取旧稿，重读及实测确认已修，不作为仍存在的缺陷。

合计 690 项本地检查，未发现运行时异常。此计数包含页面／方向组合及多项断言，不能理解为同等数量的独立业务场景。不是复用旧稿的 512 项结论。

已实际通过表单从零制作一个示例领取任务：添加定位与点击动作、关联前序输出、创建点击次数配置、绑定配置、选择资源、增加核对步骤，自动生成只读 JSON 并通过本地定义校验。另验证了复制任务、调试有序动作、暂停后继续未完成步骤、重做当前任务、未知结果阻断、授权撤销迟到回调、一次上传的成功／确定失败／未知／权限失效，以及完整任务集保留其他任务。

事件与账号的旧模拟器情境使用显式画面外 legacy resume 夹具推进，不借此证明新的恢复执行逻辑。初次直接迁移旧事件脚本时有 11 项因旧“双击暂停即恢复”假设失效；修正评审夹具后保持事件断言，55 项通过。首次开发者越界检查误选滑块，浏览器将 -1 夹为 0；改为实际精确数值输入后验证通过，未放宽产品约束。最终删除检查最初误选仍被未知证据占用的旧版本，确认其禁用原因后，改用无占用版本验证删除，另增加了未决依赖保护断言。相关脚本保存在 [browser-checks](evidence/browser-checks/README.md)。

## 交付限制

- 主稿继续／重新开始是绑定当前 runId 的 UI 投影，底层旧模拟器仍保持暂停且未修改游标。截图与选择器可评审，不计作新的执行器实现。开发者调试也是独立页面内的单 Executor 设计夹具，未与主稿引擎接通，不代表真实共享输入锁已实现。
- 未连接 Android、游戏、Root、GitHub、视觉服务、通知或代理；未进行真实截图识别、输入注入、账号登录态提取／恢复、OAuth 令牌交换、Release 创建或发布。
- App 内“本地保存”仅当前内存会话；刷新会重置。任务资源为样例，尚无真实资源采集、持久化或上传器。这里验证的是设计路径与状态，不是生产可靠性或 24 小时常驻。
- 普通使用、制作与发布的具体 JSON 字段、动作接口、授权注册及真实任务仓库尚未冻结；本轮没有替用户作这些额外决定。
- 保留旧原型和三个模拟器及测试，[7 个旧文件哈希核对均未改变](evidence/legacy-preservation.json)。工作区无 Git 仓库，未初始化、提交或发布。

最终源码摘要、检查数量和截图索引见 [verification.json](evidence/verification.json)。
