# 简洁交互重出稿覆盖矩阵

版本：0.4<br>
日期：2026-11-15<br>
基线：[完整 PRD v2.2](../PRD.md)、用户已提出的功能与交互要求、[旧低保真 30 页清单](../prototype/README.md)。

本轮交付为完整 App 的产品原型和设计文档，不是 Android 应用实现。简化的是操作路径、信息呈现和重复配置，不减少物资、商店、御魂等已明确功能。旧页面可合并为原生详情、底单或分组设置，但其字段、动作和状态仍需可到达、可核对；不能以少量关键页面截图宣称完整覆盖。

新增用户要求：App 是管理和运行任务的容器，任务从云端拉取，以减少任务变动时发布 APK。本文增加第八节增量覆盖；此前第七节对 app-v2 的 22 任务／47 页面检查只证明旧静态夹具的范围，不证明新分发能力已经实现。云端目录和任务包不等于云端视觉模型，也不等于云端远程执行。

所有任务、画面识别、场景可执行性、模型连接和通知投递均为模拟。示例数据、商品、次数、刷新时间、预算、筛选条件与过滤映射不成为生产默认规则。

## 一 本轮八点精确审查

| 编号 | 需要纠正的问题 | 可执行验收 |
| --- | --- | --- |
| S1 | 任务路径过深 | 从任务类别点具体任务，直接进入同一个配置页，内含摘要、资源和规则，常用星标在列表；不再经过只有摘要的详情再进入规则页 |
| S2 | 无意义固定底栏 | 只有“返回列表／返回分类”的固定底栏删除，顶部返回足够；真正保存／执行操作是否固定依页面需要设计 |
| S3 | 列表运行语义 | 任务／计划未入队可添加；队列中标识且按钮禁用；当前执行按钮暂停／继续 |
| S4 | 人工接管不被其他任务干扰 | 手动暂停／停止暂停整个队列；新项可入队，用户继续前不得提交游戏输入 |
| S5 | 未知兑换优先核对 | 兑换结果不确定时第一入口是核对结果与证据；修改配置只改变未来规则，不宣布修复或自动重买 |

| S8 | 通知按类型填表 | 本机通知不出现 Webhook／Key；外部渠道只展示该类型必填目标与认证，切换类型不混用另一类型字段 |

### 完整交互约束

下列 K1–K8 保留全量交付检查，不能用精确八点修正替代范围覆盖。

以下将本轮简化原则转为检查动作；不增加业务默认或额外确认流程。

| 编号 | 原则 | 可执行检查 | 不通过的表现 |
| --- | --- | --- | --- |
| K1 | 直接在列表执行 | 在任务和已保存计划列表行右侧将一次／一轮加入队列，检查保存规则及既有日程不变；按优先级调度 | 另建执行目录、列表按钮变暂停、绕过队列或并发点击 |
| K2 | 一个常用开关 | 在任务和计划原位置切换常用，悬浮入口同步变化；刷新导航和修改规则后仍引用同一对象 | 收藏、快捷添加、快捷管理、排序页并存；先执行一次才能加入常用 |
| K3 | 当前场景内部判断 | 用模拟画面切换检查可以开始、不可开始、未知三种结果；未知显示正在识别，确定无候选才显示空态 | 把未知当不支持，要求普通用户手动配置支持页面或过滤条件 |
| K4 | 当前运行控制独立 | 启动后切换到无候选／未知画面，仍能暂停、继续和停止当前运行；工作台及悬浮球当前项呈现运行控制 | 常用项被过滤后停止入口消失；暂停未运行常用项，或错停其他任务 |
| K5 | 普通用户与开发诊断分层 | 从普通导航浏览任务和设置，仅出现有用的配置与原因；页面识别、兼容矩阵和过滤依据在独立开发诊断 | 首页堆环境／技能技术矩阵；进入开发诊断自动采集、上传或允许强制执行 |
| K6 | 预设服务只填密钥 | 选择 Gemini 或北京百炼，打开官方 Key 引导，再填写 Key；高级自定义单独折叠且默认路径不需地址和模型 | 普通用户必填 Base URL、协议及模型标识；测试失败自动换厂商／区域／模型 |
| K7 | 异常直达相关修正 | 模型认证、任务资源、渠道错误各进入对应配置；未知兑换进入核对说明；保存后异常仍待验证 | 所有错误统一“查看并处理”；改配置即标已修复或自动重做未知消费 |
| K8 | 全量功能沿用简洁结构 | 依下表逐项访问业务、表单、消息、设置与悬浮状态，在横竖屏各检查；更换排版不丢旧低保真功能 | 只重画首页／9 个关键页；商店规则、御魂强化整理或通知配置消失 |

## 六 演示与后续验证边界

原型可用 fixture 切换庭院／商店／战斗／未知等场景，但必须在评审说明中明确是假设示例，不声称已识别游戏或实际任务从这些页面可达。开发诊断可显示 fixture 的理由；普通产品页面不变成技术教程。

权限、截图及输入、云端图片测试、通知投递、24 小时运行、主题泛化和自主新活动均须后续 Android／真实服务与游戏验证。浏览器点击顺畅不等于这些能力完成。

重出稿检查顺序：先静态核对全部内容与入口 → 在浏览器访问所有页面和关键状态 → 横竖屏回归 → 执行 S1–S8、K1–K8 与场景三态交互 → 导出完整页面组图与覆盖结果。截图数量不是完整性的唯一依据，必须能从每项要求找到其原型位置或明确缺口。

### 7.3 已反馈问题与修复复核

3. **交付数量说明不一致，已更正为实数。** 原反馈称 23 个任务表单，实际为 22；不为凑数新增玩法。本矩阵不以 23 作为产品验收门槛。
