# 架构验证与重审清单

版本：1.0-draft；日期：2026-11-15。对应[系统架构草稿](system-architecture.md)及[选择记录](architecture-decisions.md)。全部是待执行验证，不是通过清单；不重新安排产品分期。

## 先审内容层次和唯一控制链

1. Action提供基础能力，Step编排动作，Task包含多个步骤及一组配置schema；任务本次数据记录配置值、进度和结果，没有独立pause/resume状态机。
2. Plan只有任务集合＋时间，开始／结束及列表状态由执行器关联事实派生。
3. 所有页面、计划投影和悬浮控制都调用同一个Executor.pause()或Executor.resume(mode)，只有一个执行器状态图。

旧原型还包含PlanRun／checkpoint等接口，不能直接当正式实现模板。此前[72内存情境／512浏览器检查](verification-settings.json)属于旧基线，本轮未重跑，也不证明最新设计已实现。当前无Android工程或本项目目标设备实测，未操作真实账号／服务。后续只读复核发现本机已安装但未加入默认 PATH 的 ADB 与 JDK，见[开发环境记录](../development/environment-audit.json)；存在工具不代表已验证真实输入与截图。

## 核心行为验证

| 场景 | 应证明什么 |
| --- | --- |
| 暂停时输入在途 | pause立刻禁全队新输入；静默前显示暂停中，独立确认后才已暂停，计划／任务页没有自己的暂停状态 |
| resume(continue) | 完成步骤跳过，未完成步骤从入口新观察，不整任务重头、不续跑旧坐标 |
| resume(restart_current_task) | 当前任务step1，其他任务不变；同包／规则／累计消费不清零，旧尝试事实不覆写，不重入整份计划 |
| 动作与步骤表达 | 同一动作集合表达代表任务；配置值与动作输出正确传递，业务完成有核对依据；步骤重入不续跑旧动作现场，不盲目重复未知消费 |
| App制作与调试 | 不手写完整JSON即可选动作、编排步骤与schema；草稿可在App内单步试跑并定位错误，调试复用唯一Executor且不混跑托管 |
| 恢复过程中再次暂停 | 同一执行器取消本次恢复，旧观察／工作器结果不能推进新步骤；输入静默前不显示已暂停 |
| 兑换结果未知后两种恢复 | 先核对，确认未生效才重做；unknown不变成失败、暂停／删除／切号不能清证据 |
| 整份优先级与合法候选 | 计划30当前成员10仍高于独立25；同分FIFO，只有账号／能力合法项参与，原号高优受阻项不抢新号任务 |
| 失败与重做 | 确认失败记录后继续后续任务；重新开始只能由用户明确选择，无自动重试 |
| 去重与定时 | command／occurrence幂等，顶层ref不能重复live；计划保存登记日程，到点只提交集合，不解除暂停或借新账号执行 |
| 停止与移除 | 保持已确认范围；停止hold全队，移除不新设／解除hold；静默和业务结果安全前不交接 |
| 任务工作器卡死／旧回调晚到 | 独立桥可撤销旧输入资格，不等旧工作器；旧模型／回执不能推进新步骤 |
| 桥断联／进程被杀 | 不把kill或timeout当输入静默，不假装游戏操作未生效；新会话不能复活旧输入 |
| 页面旋转／切App／浮层 | 同一Executor及队列、同份草稿，当前控制不因场景过滤消失 |
| 规则／投递存储失败 | 已提交业务结果不回滚、不锁业务输入门；无法写业务动作意图则另属安全失败 |

## 平台与真实能力验证

| 范围 | 必须留下的证据与限制 |
| --- | --- |
| Android能力 | 代表手机／Windows模拟器的实际游戏截图、受控输入、窗口／方向、授权失效；记录Android／ABI／安装身份，不由公开API推导兼容 |
| 独立输入桥 | IPC调用者、重放、双连接、撤销与静默时间线；不可中断native阻塞和系统整体停止分别报告 |
| 本地多主题 | 已适配与留出主题分开，文字／目标／关键数字及误操作分项；模型关闭仍有真实任务闭环 |
| 云视觉／陌生活动 | 图片、结构化提案、坐标映射、取消／晚到、费用未知；完整记录人工帮助和专用修补，不因读懂规则声称自主完成 |
| 任务集更新 | 同容器切两个完整版本；缺原语／未知widget明确不兼容；运行／未决不换版；损坏／断网／路径越界／文件与DB中断不暴露半套资源 |
| 上传即发布 | 作者明确上传后形成可拉取新版本，无云草稿／额外发布步骤；凭据不进JSON，原任务集其他内容保留，失败不替换旧可用版本，不替消费者启用 |
| GitHub开发者保护 | 授权登录后核对指定任务仓库权限；只读用户／任意fork写权限不能解锁，令牌权限及组织限制能区分；权限撤销／失效／未知不按成功开放，最终由GitHub校验Release写入 |
| 版本引用 | 入队／启用／删除竞态、共享资源、晚到下载；保留当前／恢复引用，删除不删规则／计划／历史，不伪造释放成功 |
| 登录态 | 同环境A→B→A、停止／数据静默、兼容、提交中断、错号与回退、新UID／区服／渠道证据；文件存在或hash一致不是登录成功 |
| 账号隔离 | 实际核对成功且换号才清旧live，失败保旧队列，原计划保原号，删快照保计划／历史，始终等用户明确恢复 |
| 日程／启动 | 时区／时钟变更、重启／错过／前轮重叠、后台唤醒；未定策略不能由技术默认补做，开机自启不自动游戏／resume |
| 11项事件规则 | 关闭时消费离散事实后开不回放，持续episode一次，人工暂停冻结相关计时；计划事件由任务事实汇总，无订阅仍留事件 |
| 六类通知 | 保存／显式测试／实际订阅分开，真实业务码、超时／发送中崩溃、渠道接收≠已读；未知不无依据重发 |
| 三域代理 | model／task-source／notifications分别验证HTTP／SOCKS5、认证／DNS／TLS与SMTP；未选域直连、本机不联网、在途保route、失败不静默直连 |
| 秘密与存储 | 连接变化不复用旧凭据，日志／导出不含秘密；容量不足、数据库迁移／损坏有可评审恢复，不清库换启动 |

Root路线详细矩阵见[游戏与账号边界](game-lifecycle-account-boundaries.md)。这些实验需明确目标环境、已有授权及恢复办法，真实资源消费、发送消息与发布部署分别核对范围；架构设计不自动授予操作权。

## 24小时与资源生命周期

分别在支持真机和模拟器持续运行，覆盖等待、任务切换、用户暂停／恢复、错误与授权失效。记录任务实际结果／误操作、输入独占、Java／native内存、CPU／温度、网络请求、磁盘和引用趋势，不能以进程存活代替任务可靠。

验证帧和工作器有界背压，慢OCR／模型／断网不无限积压；Bitmap／Image／native buffer、推理session和投屏资源在完成／取消／异常时释放。日志截图按留存与恢复引用清理，动作证据不被新帧偷换。分别测禁新输入、静默确认和业务核对时长，不用按钮变色当实际生效。

采样频率、容量、准确率、超时和性能门槛以实验数据形成建议再冻结，本文不编生产数值。

## 每次验证怎么交付

记录问题／对应需求、容器／任务集／规则版本、设备和安装身份、步骤、预期事实、实际时间线、证据、失败分类和恢复结果；不包含登录态／密钥原文。代码修复需实际接口修前失败与修后通过，无法做旧对照就标明。

本轮只完成待重审设计，未重跑旧测试、未做Android或真实服务实验。评审、内存测试、平台测试、真实业务和长期运行证据必须分开，不把写稿完成说成架构通过。
