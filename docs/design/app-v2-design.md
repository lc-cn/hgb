# App v2 交互交接

日期：2026-11-15。基线：[PRD v2.4](../PRD.md)。本稿交接完整原型与已确认交互，不表示 Android、游戏输入、真实网络或通知服务已交付。实现与验证记录见[设置收敛](settings-convergence.md)和[执行交付](execution-convergence.md)。

## 页面与内容归属

五个主入口为工作台、任务中心、托管计划、历史记录、设置。22项云任务缓存夹具归入六类业务；类别与周期标签不复制任务。主导航只在顶层显示，详情用顶部返回。普通界面保留操作、资源影响、输入约束、费用和错误原因；帮助、内部契约及模拟说明分别进入帮助、开发诊断和设备框外。

- 工作台管理同一引擎的当前项、等待／自动挂起队列、移除与异常入口。
- 任务中心配置具体步骤集合、目标、资源与保护条件，列表正文直达配置。
- 计划组织有序任务及执行时间，复用任务配置，优先级展示成员之和。
- 历史记录仅有“通知”“运行”两标签，不设“待处理”标签。异常详情与工作台入口保留。
- 设置中只设一个“通知管理”，内部进入通知渠道、事件规则、事件记录；另有账号资料与开机自启、模型、网络、授权、悬浮与数据配置。游戏启停与账号选择集中工作台标题栏。

## 横竖屏与控件

评审尺寸为竖屏412×860、横屏900×412，保留紧凑顶栏和五主导航。横屏任务中心为窄分类区和双列任务；计划列表双列；任务表单短字段并排、大文本／多选跨列；计划参数与任务编排分区，模型服务区与连接区按内容分列。工作台主列保留控制和异常，副列先展示队列，再放下次计划，避免队列被挤成零高度。历史记录横屏为左侧112px标签栏、右侧独立滚动记录区。

设置与通知管理入口横屏两列、竖屏单列。工作台当前任务名是主文本，phase／优先级是次文本；移除重复运行更多菜单。最近结果保留实际记录，不再用全历史计数显示“今日与本周”进度。

各横屏滚动区按页面、实体和面板记忆位置；竖屏非滚容器的零值不覆盖横屏记忆。场景候选的滚动键含观察版本。方向、导航和局部刷新保留草稿、层级与运行，异步下载不重建无关编辑表单。

普通参数单选用单选按钮组，多选用多选按钮组；**模型服务商按用户指定使用原生下拉，工作台未启动时的账号区可下拉选择启动账号**。按钮组竖屏纵排、横屏横排并换行。有限范围采用滑块与精确数字联动，次数／预算不虚构上限；时刻和日期用原生选择器，时长用小时／分钟数值。非法值保留并明确提示，保存执行同一字段约束，不静默取整。独立日期示例不增加日期调度业务。

## 云目录与版本

App是稳定任务容器，任务定义、步骤、识别资源与表单描述独立更新。任务中心顶栏显示当前版本，已知远端不同才显示小红点；无版本显示“未启用”，不伪造更新状态。设置引用同一任务更新页。

任务更新只列本地版本与更新时间，行右启用／删除；当前项为禁用“已启用”，有占用的删除置灰并提供无障碍原因。正文展开／收起changelog，按钮不触发展开；顶栏手动拉取。启动只自动拉最新版一次，不因导航或旋转重触发，不覆盖所选旧版。删除、回退和更新不清理用户规则、常用、计划或未知结果。

已选、在途下载以及所有未结束执行项／未决结果依赖的包受占用保护；运行锁定包与配置，更新不能替换在途内容。拉取失败保留本地内容与已知远端信息。真实云传输、完整性、兼容核验和任务运行时仍待实现，见[容器架构](task-container-architecture.md)。

## 任务、计划与执行队列

任务步骤为只读details，默认收起，按需展开。计划编辑已选任务行支持移除引用与排序，候选仅显示未选任务，不重复选中项；移除不删除原任务。

常用星标位于任务／计划列表行右侧，引用同一实体布尔值，详情不重复开关，不另设收藏或快捷管理。任务／计划未入队时按钮加入队列；队列中显示标识并禁用重复提交，当前项显示暂停／继续。各入口操作来自同一执行快照，不维护页面状态副本。

计划周期仅“每日”“指定星期”，单选周一即每周一。有效保存后日程生效，不立即插入本轮；时间、任务及所需星期缺失时拒绝保存，不另设周期开关。结束条件为本轮完成，可选最长时长，保存结构化 `endCondition`／`maxDurationMinutes`；不使用自由规则或时钟假装时长，也不新增重复轮次。时长到限策略仍待确认，原型没有真实计时器。

任务与整轮计划进入同一优先级队列。整计划分数在提交时锁定，不因当前子任务或剩余任务改变。严格更高优先级在旧输入安全静默后交接。继续时跳过已完成步骤，未完成步骤从入口重新观察并执行，不恢复动作中途状态。另支持重新开始当前任务：独立任务从第一步，计划仅重做当前任务，保留已经完成的成员。原尝试结果与消耗保留，未知结果先核对，不能盲目重放消费。确认失败记录原因后继续后续任务，计划区分部分失败。任务包步骤与优先级示例不是生产默认。

步骤级继续与重新开始是本轮新确认的设计语义；现有可点击原型没有新增重新开始入口，不以原型存在宣称该功能已实现，具体操作位置后续对齐。

暂停统一交给任务执行器；恢复时选择“继续”或“重新开始当前任务”，两者只是恢复动作的区别，不增加任务／计划各自的暂停／恢复状态机。计划只有集合与定时提交职责，列表排队／运行信息从任务和执行器派生；原有全队人工暂停与整计划合计优先级保持。

人工暂停或长按停止均全局等待用户继续；停止另取消本轮当前项，其他队列及未来日程保留。继续先重观察、核对，再按统一优先级选择，不优待原项。工作台与悬浮当前控制短按暂停／继续、长按停止；手势绑定按下时runId，移出、取消、转向或重绘撤销计时，长按后不补短按。网页判定数值不作为Android阈值。

工作台支持右滑移除当前、等待及挂起项，并提供小型无障碍行操作。移除不新设人工暂停；已有人工暂停也不因删除解除。在途项先撤销执行器代次与输入权限，由独立输入服务确认静默后交接，显示“移除中”，不依赖卡住任务返回。未知结果和证据保留，不能用删除行掩盖。

## 一套三层悬浮

小球 → 快捷面板 → 常用列表。快捷层放唯一当前运行行、常用入口、简短异常与返回助手；常用层复用同一运行行，候选单独滚动，横屏可双列。返回回快捷层，关闭收起到球；这些操作及隐藏均不暂停或停止执行。不恢复A/B/C选择器。

当前运行不参与候选过滤，即使场景未知或无候选仍可控制；人工暂停且无当前项时提供继续队列入口。常用候选由原实体属性与当前场景判定派生，包含正常导航可达；未知不当作确定不支持。复杂编辑回主App。场景映射仍为评审夹具，不能据此宣称真实游戏兼容。

## 模型服务商

服务商原生下拉，右侧“配置”，另有“新增”；只有点击配置才铺开字段。内置服务普通路径填密钥，官方获取链接及按需小帮助可达；新增具名服务配置名称、协议、地址、模型与密钥，保存后进入列表，可取消且不自动开启模型。

每个provider独立保留未保存草稿、已保存连接与凭据。选择、旋转和取消不隐式保存或测试；变更服务、地域、目标地址或协议不能复用错误归属的密钥。保存与主动能力验证分开，保留必要费用提示。预设核验见[模型文档](model-presets.md)，原型测试不调用真实服务。

## 通知管理与事件规则

设置仅“通知管理”一个入口，页面关系为 `notification-management → channels / event-rules / event-log`。旧 `notification-rules` URL仅兼容转到管理页，不再是独立排队阈值页。

六类渠道为本机、钉钉、企微、Bark、邮件、自定义Webhook；按类型显示目标及认证，本机不显示外部凭据。列表右上添加，编辑页右上测试／保存，无重复底栏。测试当前草稿不隐式保存，只记测试投递，不产生业务事件。凭据与渠道、目标及认证身份绑定，切换不串用。

规则owner与渠道owner独立：**规则 → 事实事件 → 已启用渠道的订阅 → 投递记录**。无订阅也保留已触发事件；渠道接收不等于已读或异常解决，投递失败不控制执行。

首批11项为：任务开始、任务成功、计划开始、计划结束（结果筛选）、连续执行失败、结果待核对、排队等待过久、执行无进展、运行条件中断、资源或容量受限、视觉服务异常。全部默认关闭；编辑建议预填仅为本项目选择：连续失败1次、排队10分钟、无进展5分钟、资源10分钟、视觉2分钟。不是上游默认，也不是已验证生产阈值。

正常恢复不重复开始事件，开启规则不补发旧离散开始／成功／结束事件。同一持续条件不每帧重复触发，排队与无进展排除人工暂停／核对等不适用时段；正常战斗、可靠识别的等待不冒充无进展。规则只提醒，不自动取消、重试、恢复、购买或换模型。重复／静默等进一步策略仍待决。

完整11项表与边界见[PRD 6.1](../PRD.md)，来源见[事件规则依据](../research/event-rule-rationale.md)，所有权见[事件通知架构](event-notification-architecture.md)。

## 网络设置

`#network`提供直接连接／使用代理。代理类型HTTP／SOCKS5、地址、端口、认证方式；可选用户名密码。使用代理需明确选择类型、有效地址、整数端口1–65535及范围，不能猜测；范围多选视觉模型、任务更新、外部通知（内部scope：`model`／`task-source`／`notifications`）。默认直连、范围为空。

只有已保存配置决定请求路由，草稿不影响当前路由。保存不发网络、不测试、不重试；显式测试只是本地模拟配置检查，不是连接成功。代理不等于系统VPN，不接管游戏或其他App网络。密码私有且随目标身份绑定，不串用或公开导出；真实传输兼容仍待验证。

## 工作台标题栏游戏控制与账号管理

游戏状态与工作台标题同行：账号区显示“大区 · 昵称”；未启动时可下拉选择启动账号，并使用相邻图标启动。启动后禁用切换；运行且当前账号尚未保存时显示保存登录态图标，旁边另有停止游戏图标。标题不叠加大卡片或常驻说明。图标具备明确标签，停止游戏不冒充停止某个队列项。

身份待核对、恢复失败或能力不足时，内容顶部按需展示原因及相关操作；不把目标账号当成已核对当前身份。设置只保留账号资料管理与开机自启，`#accounts`／`#account/id`管理本地快照资料、改名和删除，不重复游戏启动、采集或账号选择。旧独立游戏操作页不再是正式入口。

采集只从工作台未保存账号的图标进入，点击先短确认说明需要暂停并关闭游戏；确认后复用既有登录态提取流程，在内存演示中停止游戏再保存；不是不中断运行的即时保存。保存仍为未验证，真实一致性策略需设备验证。

宿主在启动、提取或强停前暂停调度，等待独立输入静默；游戏会话模块不拥有scheduler。Root受控路线仅是用户接受的验证方向，普通能力默认unknown／尚未检测，不能据演示模式假定设备已Root。登录态快照在产品上是可复用会话状态；原型只存元数据和私有占位handle，公开API不含会话内容。

保存快照标未验证，恢复进入`awaiting_identity`，新的UID／区服／渠道观察匹配后只标`verified-demo`。同设备、渠道和游戏版本须兼容；错误身份为failed并保留切换前回退元数据。rollback进入`awaiting_rollback_identity`，新观察核对原身份后才完成回退；迟到操作或旧观察不能覆盖新阶段。

身份核对pending或failed时禁止Continue。仅新身份成功核对且实际账号改变后，宿主清空全部旧未结束执行项，新账号重新添加；历史和unknown证据保留，失败或回退不清旧队列。成功也保持hold，仍需用户继续。`accountBinding`只锁opaque key与名称，不将登录态bytes或句柄带入执行器。

计划在创建／保存时绑定账号，已有计划编辑不自动改绑。计划列表、工作台下次计划按当前账号筛选；切号保留原账号计划，新账号重新创建。原账号计划到点仍锁原`accountBinding`并等待匹配账号，不使用新号执行，不自动切号／补做。删除本地快照不删除原账号计划或历史。

任务结果、最近结果与完成摘要只读取当前账号的数据；全局历史记录不按当前账号清空，逐条标明账号来源，避免跨账号冒认完成。

开机自启只保存助手偏好；评审boot事件只恢复助手到待授权／身份核对，不解锁、不启动游戏、不切账号、不恢复队列。能力、A／B已登录观察、新身份确认及boot只在设备框外模拟，不是正式权限入口。默认庭院账号A是假元数据。当前没有ADB或Android连接器，没有真实提取／恢复、跨设备或免登录证据，见[官方能力边界](game-lifecycle-account-boundaries.md)。

## 记录、异常与交付边界

历史记录仅通知／运行两标签；通知管理的事件记录保留触发来源及关联投递。认证、资源和渠道问题通过工作台／异常详情进入相关配置，未知结果先核对实际证据。保存配置、通知已投递、更新任务包均不清除未知或自动重做。

开发者模式改为受保护入口：通过GitHub授权登录，核对指定任务仓库的有效权限后进入，只有项目负责人及其通过仓库权限指定的开发者可用，不保留任何人可直接打开的开发开关。模式内包括任务制作、App内调试、生成JSON及明确上传即发布仓库Release，保留观察、版本和输入归属诊断。制作建议采用动作参数表单、步骤列表和配置字段编辑，调试展示输入输出与错误位置；详见[任务制作设计](developer-task-authoring.md)。GitHub实际校验发布权限，不因进入模式自动上传，不扩大游戏执行权限，令牌不进入JSON。当前原型仍只有旧开放诊断开关，授权保护及新增编辑／调试／发布均未实现。

[原型](../prototype/app-v2.html)的设备外工具条只注入场景、逻辑时间、执行事件及游戏能力／身份／开机演示。可用 `?orientation=landscape`、`?view=game&layer=common` 和既有board组图审阅；模型、`#notification-management`、`#event-rules`、`#event-log`、`#network`、`#accounts`及`#account/id`为设置／管理入口，游戏状态操作直接在`#home`标题栏。页面存在、浏览器验证与模拟事件均不证明24小时驻留、跨主题、新活动理解、真实截图输入、网络路由或真实投递已经完成。
