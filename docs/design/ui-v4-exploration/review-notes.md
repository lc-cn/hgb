# UX 重设计：先验证三个关键场景

本轮是待评审的布局探索，范围为工作台、任务中心和三层悬浮的横竖屏。不是完整 App 已重新定稿。旧 v3 和 PRD／架构保持不变。

[打开同场景新旧对照](index.html) · [体验新布局](app.html) · [设计决策与具体取舍](design-decisions.md)

## 重新采用的方法

上一轮主要验证功能、状态和布局溢出，不能据此证明界面更容易用。本轮先问：第一眼应看到什么、常用操作在哪里、名称和图标是否表达真实后果、是否需要反复往返、悬浮窗是否把游戏挡住。专家审视与本地点击观察仍不能替代实际用户测试。

实际读取并运行了本地 [UI/UX Pro Max](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill) 的设计系统、UX 与 Compose 查询。通用生成结果误配到 App Store 落地页和 AI 聊天，未使用这些模板、字体或配色。使用了触控、间距、反馈和导航的一般建议；技能检索结果不直接决定产品。

进一步参考 [Mobile UI/UX Pro Max](https://github.com/noumanzindani/mobile-app-uiux-pro-max-skill/blob/main/SKILL.md) 的用户目标、信息层级、拇指触达和原生平台检查，以及其平台、密度、导航和列表详情规则。它作为设计参考，未全局安装，也未把通用技能的完整合规要求当成本项目已实现能力。未新增深色模式、账号体系或技能示例中的功能。

平台取舍对照 Android 官方的 [布局基础](https://developer.android.com/design/ui/mobile/guides/layout-and-content/layout-basics) 和 [典型自适应布局](https://developer.android.com/develop/ui/compose/layouts/adaptive/canonical-layouts)：把主要内容与辅助内容分开，宽屏可保留列表和详情上下文，方向变化保持所选项与草稿。原型像素不等于设备 dp，不据此声称 Android 实机或无障碍认证通过。

## 这次实际改变什么

| 场景 | 结构变化 | 保留的约定 |
| --- | --- | --- |
| 工作台 | 队列占正文主体；唯一当前执行条固定在下部；当前任务名、步骤与暂停组成一组，明确“移除”以免误认为收起 | 当前账号与游戏图标同行；暂停／停止与移除后果不同；执行结果仍可达 |
| 任务中心 | 一行文字分类；去重复业务图标；行尾直接表达入队和队列中；横屏周期放进顶栏，减少一行筛选；配置与列表同屏 | 六类、周期过滤、列表星标、加入队列、原 schema 与版本入口 |
| 长配置 | 竖屏保存固定在路由栏；横屏保存固定在配置栏顶端 | 正文直达配置、按钮组、保存不入队、旋转不丢草稿 |
| 三层悬浮 | 快捷层压为当前控制＋工具行＋按需短异常；常用不重复任务／计划副文，排队项原位显示“队列中” | 小球→快捷→常用、唯一当前、自动候选过滤、行尾小图标 |
| 横屏 | 同五入口改为窄导航轨；列表／配置分栏，布局按实际内容安排 | 不增加主导航，不新增业务或调度规则 |

图标仍为 20px，悬浮透明命中区为 48px，暂停与停止相隔 8px。实际拖至左下角后，面板按视口空间向上展开并限制越界；球位不改变。这是基础弹层边界适配，不是识别游戏后自动躲避。当前控制固定，只有候选滚动。

## 同内容比较

两侧使用相同账号A／demo-server、每日物资托管计划（总优先级30）、当前每日物资领取、三条等待项（御魂25、悬赏10、结界挂卡10，均7分钟）及一条商店未知记录。为避免无关错误造成不公平，旧稿评审夹具也只保留这一条未知记录。新稿22项名称、schema、值及步骤从 v3 原样导出到 [fixture-data.js](fixture-data.js)，没有用精简任务或虚构参数衬托新布局。

[布局观测表](layout-observations.md)记录截图实际几何值；[旧稿观测](before-observations.json)、[新稿观测](after-observations.json)保留原始值。这些只能支持位置与矩形覆盖面积的结论，不能推出找任务更快、误触更少或真实游戏完全无遮挡。

## 实际操作观察

已用本地浏览器在两个方向完成以下路径，结果见 [walkthrough-observations.json](walkthrough-observations.json)：

- 读出当前任务和下一项，暂停后队列保留，再选择继续。
- 星标一击切换且不进入配置；入队后原位显示队列中并禁用，当前执行不被误显示为已结束。
- 修改既有字段，旋转保留选中项和草稿，保存不修改在途计划优先级。
- 御魂长表单滚至底部，保存仍可见且能收到指针点击。
- 小球进入快捷后暂停，再进入常用；未知场景候选隐藏，当前控制保留。

另做了实际拖动边界和长常用列表观察，见 [edge-observations.json](edge-observations.json)：两个方向拖到左下角展开，面板和当前控制均在边界内；常用列表滚到底后当前控制不移动。没有用大量页面断言替代这几条操作体验。

## 仍需取舍

- 横屏列表与配置同屏使返回次数减少，但配置打开后同屏任务数会减少；需要大字段时仍会滚动。
- 一行类别节省高度，但竖屏部分分类需要横向移动才能到达。没有把“少一行”直接等同于分类更容易发现。
- 底部执行条便于下部接管，也降低了当前任务在页面顶部的显著性；应由实际使用判断。暂未增加全 App 常驻执行条，避免一边保留行内暂停、一边堆重复控制。
- 快捷层明显变矮；常用层为了清楚显示名称和足够命中区，竖屏宽度比旧稿大22px，面积收益较小。没有只挑有利指标。
- 当前任务包、执行器、游戏、模型、网络与 GitHub 都没有在此重新实现；其余页面链接完整 v3。这份夹具只用来评审布局，不作为生产调度器或持久化实现。

布局尚待用户评审；本轮完成意味着有清楚的新旧方案与可观察差异，不代表审美或真实使用体验已经获认可。
