# UX v4：两种结构方向，待统一评审

本轮只做 UX 方案，不写界面代码，不修改 v3，不将任一方向视为用户已认可。讨论对象为工作台、任务中心和游戏内三层悬浮，横竖屏都从信息职责重新布局，不继承 v3 的 CSS、DOM 或卡片尺寸。

## 依据与不可变边界

已阅读 `ui-ux-pro-max/SKILL.md`，运行设计系统查询 `Android game automation utility task queue native mobile compact landscape`，补查 touch target / information hierarchy / progressive disclosure，以及 Jetpack Compose adaptive compact height。设计系统误匹配为 App Store 下载页、AI 聊天界面；Compose 查询只返回不可变集合。它们不适合此产品，因此不套用其页面模式、配色与动画。采用技能中触控命中区、相邻操作间距、非仅颜色反馈与清楚层级原则。技能不是自动决定产品的依据。

现场图依据：`ui-v3/screens/main-workbench-running-{portrait,landscape}.png`、`main-tasks-{portrait,landscape}.png`、`overlay-quick-landscape.png`、`overlay-common-portrait.png`，均实际查看。截图是原型证据，不能证明 Android 实际触控面积或系统兼容性。

保持：五主导航、六任务分类；工作台标题同行的大区昵称和游戏图标操作；任务/计划行星标及加入队列，版本号和红点入口；不新增首页统计、云能力、确认流程。暂停作用唯一 Executor，暂停/继续/长按停止语义不改，恢复选择不转移到计划。队列右滑移除语义不变；账号范围、异常安全门槛和在途版本锁不变。悬浮仍只有球→快捷→常用三层，开关层级不影响执行，当前行唯一且不因场景过滤消失。五主导航仍保留底部，不借横屏改成另一套产品入口。

## 原稿为什么仍像交互稿换色

1. **工作台空间由组件尺寸决定。** 竖屏当前执行区约占上半屏的一大段：状态、任务、计划、进度、记录链接各自一行，真实操作只有暂停与移除。等待队列排在完整摘要之后，常态下更频繁的“接下来做什么”没有得到对应空间。最近结果与下次计划又延长浏览路径。横屏虽修掉矮窗，左右仍是同样组件重新分栏，缺少独立的短屏取舍。
2. **任务中心把分类当成一组表单按钮。** 竖屏六个长标签折成两行，再加周期筛选；尚未看到任何任务，已有三行导航控件。每项礼物图标重复，不能区分任务，反而与任务名、星、播放争空间。横屏两列任务解决数量，却没有利用较宽空间降低“点详情→回列表”往返。
3. **悬浮面板重复 App 的列表节奏。** 快捷层含 App 品牌标题、当前行、常用行、异常行、返回助手行，逐条均等排布。用户只想暂停时仍打开一张完整小页面。第三层标题与行分隔继续占高；竖屏大块悬窗与游戏中心区域竞争，横屏没有明确的遮挡预算。
4. **视觉主次与行动主次脱节。** 工作台暂停是胶囊，悬浮暂停是小图标，同一域控制没有一致的大小等级；任务行各个装饰图标等权。这里需要先决定“用户先看什么、手指去哪里”，再选字重和颜色。

## 方向 A：上部执行摘要，队列主导；按宽度展开任务配置

适合经常切回助手安排一串任务、需要一边看列表一边调规则的使用方式。

### 工作台

**竖屏**：标题账号区下方先放按需异常短行；其后一个紧凑执行摘要，任务名主行、计划名和进度次行，右侧固定暂停/继续与移除小图标。正文主体为等待队列。下次计划、最近结果在同一连续内容流的队列之后，不开第三个滚区。运行记录链接收进执行摘要的正文点击区域，依然一次进入原记录，不增加新菜单。

**横屏**：执行摘要变为跨内容宽度的两行控制带，不再占据一整列；其下左侧约 2/3 是队列，右侧约 1/3 是下次计划与最近结果。内容不够高时，只有两个有实际内容的滚区；摘要与异常始终可见，不再在窄窗里滚动。队列至少占可用正文一半高度，不能被空结果分区挤掉。

```text
竖屏                       横屏
标题 · 账号 · 游戏操作       标题 · 账号 · 游戏操作
[按需异常]                 [按需异常]
当前任务/计划  暂停 移除     当前任务/计划  进度       暂停 移除
队列                       队列（宽） | 计划/结果（窄）
下次计划、最近结果          五主导航
五主导航
```

**路径**：看当前与暂停无需滚动；队列右滑不经过详情；记录仍一次点击；异常仍直接去原核对/配置入口。主控不因队列滚动而移位。

**代价**：横屏控制带吃掉一些队列高度；在小屏或长任务名下须优先允许标题两行，不能靠缩成小字凑宽。异常和控制带合计高度上升时，右侧摘要首屏内容会减少；这是对当前控制的明确优先，不假装所有信息能一屏全露。

### 任务中心

竖屏把六分类改为一行可横向滚动的原生文字 tabs；周期筛选保留其下一行。任务行取消重复礼物装饰，正文左对齐，右侧星标和入队位置固定。版本入口仍在标题右侧。分类可见范围不足的代价是需要横向移动，当前分类保持可见，不自动切分类。

横屏采用**分类 tabs + 任务列表 / 配置详情**：列表约 38%，当前任务配置约 62%。点任务正文在右侧呈现既有合一表单，列表选中态保持；首次未选择时列表可用完整宽度，不留大块空详情。星与入队依然直接在列表行，点星不打开详情。任务步骤仍默认收起。竖屏同一点击进入完整详情，切方向保存同一选中项与草稿。

这是一项呈现提案：不会自动选择首项，也不会因为打开详情而启用、保存或入队。横屏从某个详情深链进入时展示同一任务及所属分类；返回仍遵循既有页面层级。

**改进目标/代价**：竖屏分类区从两行降为一行，任务正文开始位置至少提前一行；横屏在同分类改两个任务时，减少两次返回列表操作。代价是横屏不再以六项全部大行同屏为唯一目标，列表最多先显示约四行，换取边看边改；长表单仍需滚动，不宣传无滚动。

### 三层悬浮：靠边工具条

- 球：沿用既有位置、拖动和状态语义，不新增自动吸边/手势。
- 快捷：球展开为紧凑的**两行工具条**。第一行当前名称+右侧暂停/继续、停止；第二行常用入口、返回助手、收起。异常仅在存在时另给一行短原因+原处理动作。不重复品牌标题，不放全量进度段落。
- 常用：同锚点向可用空间展开列表，顶部返回/收起与同一份当前行固定，下方仅候选滚动。竖屏单列，横屏有空间时两列候选；当前行不进入候选网格。

**目标**：无异常快捷层不超过约两行控制内容，横屏暂停在球展开后一次操作可达，常用入队仍是球→快捷→常用→入队，路径不加层。代价是当前任务长名需要截断，完整名通过返回助手查看；不能在工具条里塞计划长名和所有进度。

## 方向 B：底部执行控制，队列占主画面；分类轨贯穿横竖屏

适合助手大部分时间作为游戏伴随工具，用户进入 App 主要看队列、少量调配，再回游戏。与 A 的区别不是颜色：**运行控制从顶部独立摘要转到拇指区，任务导航从 tabs 转到持续分类轨，悬浮采用锚定小菜单而非横条。**

### 工作台

标题账号区仍在顶部；按需身份/异常原因在标题下。主体首先是队列，随后为下次计划与最近结果。当前执行改成固定在五导航上方的**两行执行条**：主行当前任务，次行计划名/已核对步骤，右侧暂停/继续和移除。执行条正文进入原运行记录。没有当前项但手动 hold 时，同位置显示“队列已暂停”及既有继续队列；待机不常驻空白控制区。

横屏内容使用队列宽列、计划/结果窄列；底部执行条横向压成一行，计划/进度作为次级短信息，右侧控制保持固定。它与底部导航明确分隔，不把暂停变成第六个导航，也不让队列延伸到控制下面。

```text
竖屏                       横屏
标题 · 账号 · 游戏操作       标题 · 账号 · 游戏操作
[按需异常]                 [按需异常]
队列                       队列（宽） | 计划/结果（窄）
下次计划、最近结果          当前任务/进度       暂停 移除
当前任务/计划  暂停 移除     五主导航
五主导航
```

**路径**：当前控制靠近下部操作区且位置不随内容滚动；队列一进页就开始呈现，无需越过大摘要。没有额外展开当前任务步骤的动作。记录与异常的原直达保持。

**代价**：多占一个底部常驻条，竖屏列表可视高度少于真正无当前执行的空闲态；上方账号停游戏、下方停执行相距更远，但二者语义更不容易混为同一个停止。横屏若保留全部计划名会撑高执行条，因此计划名允许截短，不能把文字缩小到不可读。视觉必须避免执行条被误认为音乐播放控件，应使用任务名、步骤文案和既有图标语义。

### 任务中心

六分类形成**窄纵向分类轨**，横竖屏位置相同；每项短名称分两行显示完整含义，不只给陌生图标。版本仍顶栏，周期筛选位于右侧任务内容顶部。竖屏分类轨约占可用宽度 1/5，其余是单列任务名、星、入队；可移除非必要的行首重复图标。横屏轨不按比例无限放大，右侧是两列任务，配置仍进入单独完整页面；不会出现 A 的列表与表单同屏。

**改进目标/代价**：任一分类切换始终一个点击，不横向找 tabs，不因向下浏览任务丢失分类。任务的上沿与分类轨上沿接近，减少顶部控件叠层。代价是竖屏任务可用宽度减少，长名称更容易两行；需要以 412px 真实检查星与入队的命中区，若无法保留合理触控面积，应否决此方向而非缩小控件。

### 三层悬浮：锚定菜单

- 球：沿用既有行为。
- 快捷：在球邻近的空侧出现窄锚定菜单，当前行置顶；常用作为唯一完整文字入口；异常处理和返回助手为紧凑底行；收起在同一固定角。菜单宽度偏窄，不向游戏中央铺一张宽面板。不新增自动位置策略，现有锚点边界适配另作实现验证。
- 常用：在原菜单位置**替换内容**，不用向旁边叠出第二张菜单。保留顶部返回/收起、唯一当前行，下方候选单列。横屏优先限制高度并加宽候选到两列；底部动作不能落到屏外。用户始终看到一张面板，而不是菜单再套菜单。

**目标**：竖屏常用层宽度小于 A 的列表面板，保留更多游戏横向视野；横屏第三层最多占可用高度、不把当前控制卷走。代价是窄面板对长名称更不友好，横屏双列会提高总遮挡宽度，需要根据实际安全区截图取舍。快捷层的列表感仍可能比 A 强，必须删品牌大标题和多余分隔，不能沿用 v3 的五行等权节奏。

## 对比与统一前的选择依据

| 比较项 | A：顶部摘要 / 列表-配置 | B：底部执行条 / 固定分类轨 |
| --- | --- | --- |
| 工作台第一眼 | 当前执行与异常，再看队列 | 队列与异常，当前操作在底部固定区 |
| 常用控制手指位置 | 顶部内容区 | 底部拇指区 |
| 横屏任务规则编辑 | 同屏列表+表单，少返回 | 全宽详情，字段更宽 |
| 竖屏分类 | 单行横向 tabs，可能横向寻找 | 六类一直可见，占正文宽度 |
| 快捷悬浮 | 两行工具条，少遮挡高度 | 纵向锚定菜单，少遮挡宽度 |
| 最大风险 | 短屏固定摘要挤队列 | 竖屏窄任务列与底部固定区争空间 |

独立建议：先用 A 验证“更少往返、更少悬浮遮挡”是否成立；用 B 作为真正不同的对照，验证底部控制可达性是否值得牺牲列表宽度。不要把 A 的顶部摘要、B 的底部执行条和原稿当前大区同时叠加，否则恢复为重复控制。主 agent 统一方向后再画结构与高保真，不将本建议直接当实现授权。

## 下一轮可衡量评审（目标，不是已实现结果）

1. 使用相同夹具：当前计划含两任务、三条等待、一个未知结果；另测无当前但 hold、空队列、长名称、权限异常。412×860 与 900×412 皆无正文被底栏截断。
2. 工作台当前任务、暂停和简短异常在首屏完整，等待三项中至少两项完整可读；横屏不出现高度不足一整行的独立滚动窗。A/B 若达不到，先调整职责，不缩小正文或控件。
3. 任务找一项→星标→入队不进入详情；改两个同分类任务对比返回次数。已有在队禁重与失败提示不因布局改变。
4. 正文目标 14–16sp、辅助不低于 12sp；图标视觉大小与实际命中区分离，常规触控目标以 48dp 作为 Android 设计验收目标，相邻目标不重叠。原型 px 不能直接当设备 dp 合规证明。
5. 悬浮分别量实际覆盖面积、打开到暂停次数、当前控制在候选滚到底是否可见、长名截断数量。快捷层只承担必要操作；不得为面积达标丢停止或异常入口。
6. 旋转后当前页、分类、实体草稿、滚动归属、悬浮层级和运行不丢；暂停中/核对中/移除中不可多发命令。恢复步骤依然以真实 Executor 合同为准，不能用视觉“已执行”遮盖 UI 评审态。

本轮未访问浏览器、未写 HTML/CSS、未修改运行或调度行为。官方 Android 尺寸与短屏布局依据由主 agent 同步研究后合并；此文未把技能的泛化结果冒充官方规范。
