# v3 → v4：独立 UX 审视

本轮看的是「看懂、找到、准确操作」，不是按钮有没有实现。依据为 v3 的工作台、任务中心、快捷／常用悬浮面板的横竖屏截图，以及运行中工作台截图。以下是基于界面的专家判断，尚未通过用户使用测试；前轮 690 项功能检查不能证明这些判断已被验证，也不能证明体验良好。

已读取并应用 `ui-ux-pro-max`。其 design-system 检索返回了 App Store 落地页、巨型字体及大量留白，明显不适合本产品，未采用。补充 UX 检索中的触达面积、邻近控件间距及信息层级用于审视；没有把网页 hover、营销布局、固定配色或精确像素建议当成需求。此次不改 v3，不写实现代码。

## 不能被重设计改变的约定

工作台负责执行状态与队列；任务／计划列表右侧是加入队列，常用星标仍在列表行。暂停属于唯一执行器；继续和重做当前任务的语义不变，停止与移除的队列后果不变。计划仍是有序任务加时间。工作台账号与游戏控制同行标题、运行中不能切号、尽量图标化。五个主入口、极简版本页、表单按钮组、受保护开发者模式均保留。悬浮仍为小球 → 快捷 → 常用三层，当前控制唯一、按场景过滤、控件保持紧凑。

下面的布局、层级、图标、空间分配均为可取舍的设计建议，不添加产品功能、自动化行为或默认值。

## 七个实际问题

### 1. 工作台同时强调了太多层「正在做什么」

证据：[竖屏运行中](../ui-v3/screens/main-recovery-continue-portrait.png)、[横屏运行中](../ui-v3/screens/main-recovery-continue-landscape.png)。当前任务名、计划名、再次重复的任务名＋步骤入口、进度条、本轮步骤数、运行记录分成多行，旁边又有移除和暂停。用户要跨几处文字才能拼出「当前是哪项、做到哪里、点哪里接管」。大标题已经正确改成当前任务，但周围信息仍按字段逐段堆积。

建议把当前执行区收成明确的一个控制单元：第一行任务名和暂停，第二行当前步骤／阶段，第三行一条标清归属的进度；计划名作为次要来源文案，不再重复任务名。「从步骤 2 进入」与当前阶段合并，而不是再开一行。移除和运行记录放同一行次操作区，不与暂停争抢第一视线。进度继续表达原有数据，只把「当前任务」或「本轮计划」的归属说清楚，不用整轮进度暗示当前任务进度。

必须保留：任务名是主文本、整计划优先级、暂停／移除／记录均可达、恢复语义。可改：重复文案、行数及操作分层。

### 2. 工作台的主体更像计划摘要，队列缺少稳定的空间归属

证据：[竖屏待机](../ui-v3/screens/main-home-portrait.png)、[横屏待机](../ui-v3/screens/main-home-landscape.png)。竖屏在状态与异常之后是两份计划和结果，屏幕下方大片空白；横屏把近一半可用区域长期给了「下次计划／最近结果」。截图没有排队项，因此只能确认空态下的分配问题，不能据此宣称有队列时被遮挡。用户切回工作台的主要目的却是确认当前执行和等待顺序。

建议把「当前执行＋待执行队列」做成稳定的主工作区。队列为空仍用一句简短空态保持位置感；下次计划只展示最近的一项摘要，更多从既有计划入口进入；最近结果压到该工作区之后。横屏按内容分配：当前执行区配窄一点的控制面，等待队列占主要可滚动面，计划与结果留在队列末尾的次级区。不要仅把竖屏三段搬成左右两大栏。

必须保留：队列查看／右滑移除、执行状态和结果、计划可达。可改：摘要数量、版面先后和列比例；不新增计划筛选、自动处理或新的队列规则。

### 3. 任务中心先让人辨认筛选器，再让人找到任务

证据：[竖屏任务中心](../ui-v3/screens/main-tasks-portrait.png)、[横屏任务中心](../ui-v3/screens/main-tasks-landscape.png)。竖屏六类导航占两行，下面又是周期筛选；第一条任务直到约画面上方三分之一才出现。横屏分类与周期都塞在左侧，六类刚好用满短高度，周期贴近底部导航。任务本身同类图标反复出现，周期与优先级重复在每行，辨认任务名之外的视觉劳动较多。

建议先画两种结构比较：竖屏把类别做成紧凑的一条导航带，周期作为紧接任务列表的次层；或保留完整类别换行，但显著收紧导航区与列表间距。横屏左侧只管类别，周期移至列表顶端，解除六类数量对短高度的挤压。类别导航不等于参数表单，不能因为改导航就把用户指定的单／多选按钮组改回下拉。行内保持名字突出，周期／优先级集中为一行低干扰次文，不靠增添说明解决。

必须保留：六类任务定位、周期过滤、行内星标与加入队列、任务正文直达配置。可改：导航形态、筛选层级、重复类别图标的占位。若采用横向导航带，需比较类别发现性与滑动次数，不能先假定更好。

### 4. 列表中的播放图标在视觉上仍承诺「立即运行」

证据：两张任务中心截图，任务右侧都是醒目的圆形播放按钮。实际约定已从立即执行变为加入队列，图标却没有随着用户心智改变。尤其执行器处于人工暂停或已有高优任务时，按完没有立刻开始，用户容易以为没点中，再去别处寻找运行状态。这是视觉语义问题，不是前轮防重复功能未通过。

建议比较「队列＋」或小型加号入队图标与现有播放图标。保留同一位置、同一控件数量；按下后在原位切换为队列中的非交互状态，让操作结果留在用户刚看的地方。当前执行项仍显示暂停，不能为了统一图标又改回绕过队列直接执行。不要在每行增加「点击加入队列」解释文案。

必须保留：用户要求的行尾单按钮、入队／排队禁用／当前暂停三种语义。可改：空闲按钮的图形及短反馈表达。

### 5. 紧凑图标解决了占位，却没有充分解决准确点按和认知分组

证据：[工作台标题行](../ui-v3/screens/main-home-portrait.png)、[快捷悬浮](../ui-v3/screens/overlay-quick-portrait.png)。标题中的保存与停止游戏和账号紧邻；悬浮暂停与停止是两个贴近的小符号。图标化符合用户要求，但「当前账号资料」与「游戏会话操作」、安全的暂停与终止操作，视觉上仍像一串同等小按钮。截图能看出贴近和分组不强；实际误触率需在可点击新稿上验证。

建议保持小图标本体，用透明触达区提供足够面积，并在组之间留间隔：账号作为完整可点资料区，启停／保存为相邻的独立操作组；悬浮中的当前名与暂停形成主组，停止在同行末端留出间距。不要放大为一块巨型停止按钮，也不要新增确认弹窗来补偿布局。状态明确后再决定是否需要一条短辅助标签，避免回到大段说明。

必须保留：标题同行、运行中禁止切号、未保存才显示保存、启动／暂停／停止同量级的紧凑控件。可改：命中区域、间距、组边界及图标辨识度。

### 6. 快捷悬浮面板在「接管当前任务」之外铺了完整菜单，层级偏平

证据：[竖屏快捷](../ui-v3/screens/overlay-quick-portrait.png)、[横屏快捷](../ui-v3/screens/overlay-quick-landscape.png)。标题、当前运行、常用入口、模型错误、返回助手每项几乎各占一行；当前显示的是计划名，正在执行的具体任务要回主 App 才更清楚。游戏里的用户只是快速暂停／查看或发起常用项，却被放进了一个缩小的主菜单。

建议快捷层压成三个区：顶端短标题与收起；中间唯一当前任务行（任务名、简短阶段、同行控制）；底部常用入口与返回助手作为紧凑工具行。异常只在这三个区之间按需插入一条相关摘要，不把普通问题做成和当前任务等权重的菜单。计划名降为来源信息。常用仍进入第三层，不取消用户已经确认的三层，也不把常用清单塞回快捷层。

必须保留：唯一当前控制、常用入口、简短异常、返回助手、收起不暂停。可改：菜单行的组织、当前任务上下文及层级强弱。

### 7. 常用悬浮把有限游戏面积花在「任务／计划」标签和行高上

证据：[竖屏常用](../ui-v3/screens/overlay-common-portrait.png)、[横屏常用](../ui-v3/screens/overlay-common-landscape.png)。每条候选第二行反复写「任务」或「计划」，而用户是自己标记的常用项；真正用于选择的名称反而被固定宽度和两列分配压缩。横屏面板宽约 486，占 900 画面一半以上。它确实减少了纵向滚动，但也覆盖了较大的游戏操作范围，不等于游戏中更好用。

建议候选采用一行名字＋行尾控制，只有队列中等会改变操作结果的状态才占次行；如确实需要区分任务与计划，用低占位的小标记，不为每项预留一整行。横屏比较「窄面板单列短行」与「稍宽双列」两个方案，以同一组长名称、常用数量和当前任务测试，不直接规定双列必优。当前控制固定在候选之外；仍只展示场景允许的常用项，不增加支持矩阵或过滤解释。

必须保留：三层、场景过滤、当前项不消失、候选可滚动、行尾快速执行／暂停。可改：候选副文、行高、单双列选择与面板宽度；不新增自动躲避或场景触发的位置变更。

## 新旧对比怎么验

让 v3 与 v4 使用完全相同的状态、账号、任务长名称、队列长度和方向；不能用 v3 空队列对比 v4 精心挑选的运行态。至少各看一次待机、运行含等待项、人工暂停、当前结果未知；截图与点击稿同时比较。

只做四个实际动作，不再以页面总数代替体验：

1. 看工作台，先说出当前任务、所在计划、下一项是什么，再暂停交还手动操作。
2. 到任务中心找一项指定任务，加入队列，并说明它是开始了还是等待；再给它设常用。
3. 游戏内从小球进入，判断当前任务并暂停，再找到指定常用项；记录打开层数、错点和被游戏遮挡的区域。
4. 横屏重复以上操作，观察是否需要整页滚动、关面板才能看关键内容，或反复左右找控制。

记录首次定位时间、滚动／点按次数、误触、是否误读入队为开始，以及口头说出的任务／计划上下文。这里只建议对比指标，不替用户设未经确认的秒数门槛。优先选在相同行为约定下减少找入口与拼信息成本的结构；若新版只是配色、圆角、字号有变化，或必须读更多解释才能操作，就不能算完成本轮改进。
