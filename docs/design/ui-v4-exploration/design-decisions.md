# UX v4 探索稿交接

入口：[app.html](app.html)。本稿从新 DOM/CSS 搭建，仅引用旧稿的颜色 tokens；没有复制 v3 整页或样式再覆盖，也没有修改 v3、PRD、执行器或其他模块。正文使用同色相更深的辅助色 `#637067`，不通过换色制造新旧差别。

## 本轮待评审的布局提案

- **工作台**：正文先看队列；当前任务移至五导航上方的唯一执行条。点正文到既有运行记录，右侧暂停/恢复及移除。待核对提示按需在正文顶部，计划/结果作为次级内容。横屏队列约占正文 65%，计划/结果约35%，独立完整滚动；没有主卡片、数字统计或多个矮窗。底部执行条横屏压为一行。
- **任务中心**：六分类是一行原生文字 tabs，周期是次层；不再有重复 gift 图标。行右星和单个入队动作位置稳定。横屏未选任务时列表可两列；选中后列表约42%、配置58%，不自动选首项。竖屏同一选中项进入完整配置；旋转后选中、草稿仍在。代价是横屏配置展开后同时可见任务项减少，换取少返回列表。
- **三层悬浮**：球→紧凑快捷工具层→常用列表。快捷层不放品牌标题；当前任务一行控制，常用/返回助手/收起同行，异常按需短行。第三层沿用同一锚点、固定返回/当前行，候选独立滚动；名称不重复“任务/计划”。横屏常用两列，竖屏单列。当前运行不因候选过滤隐藏，也不复制第二份控制。
- **横屏导航**：78px 窄轨，同五入口图标及文字，释放原底部导航高度。此为探索布局，用户尚未确认正式采用；不是新增主导航。

普通按钮目标约48px；图标20–22px。悬浮图标仍为20px，透明控制命中区48px，暂停与停止间隔8px；这是触达布局调整，不放大按钮视觉。副文11px，不再继续缩小。原型 px 不证明 Android dp 命中区合规；实际截图与设备验证后再定。

## 沿用的已确认语义

账号资料仍在工作台标题同行；任务和计划保留原引用与星标属性；列表入队/在队状态与当前控制区分。队列中禁重按顶层 `ref(kind,id)`，计划内部当前步骤不能等同一个单独提交的任务实例。例如默认整计划 daily 正在 daily-rewards，此时该任务行仍可独立入队，不被误显示成当前控制。

共享一份展示源，同时供工作台、任务行和悬浮读取；不存在三个互不相认的运行状态。暂停/长按停止、移除保持不同语义：停止当前后全队 hold；移除当前后若可继续则展示下一项；删除等待项不解除 hold。无当前的 hold 保留继续队列入口。暂停中等请求态禁用控制，页面/方向变化取消长按计时。长按600ms、右滑75px仅网页评审判定，不冻结 Android 产品阈值。

当前游戏启动/采集、历史/计划/设置、版本管理、异常核对和完整规则不在本轮重建范围；对应真实入口直链完整 v3。三个非本轮主导航直接打开旧稿，设备外明确说明。游戏标题栏保存/停止图标只提示进入旧稿评审，不假装执行设备操作，也未新增确认流程。

## 夹具与行为边界

默认与旧稿使用同一组：账号A/demo-server；当前整计划每日物资托管，优先级30，当前任务每日物资领取；等待御魂副本25、悬赏封印10、结界挂卡10，各7分钟；另一条商店兑换未知记录以短提示保留，它不冒充当前执行结果未知或擅自阻止此当前项。

这是**纯 UI 展示夹具，不是替代 execution-simulator 的调度器**：初始队列顺序固定；新提交展示追加；没有优先级抢占、安全 checkpoint、真实定时、重试、队列算法或底层输入 lease。暂停/移除的350ms和恢复的400ms只让请求中状态可见，不表示获得了真实静默确认。未知夹具只模拟当前安全阻塞，不清未知证据。不得用此稿测生产调度正确性。

恢复选择提供继续未完成步骤、重新开始当前任务；只改展示字段，不接真实执行器，也不宣称原模块已有 restart。跨账号、真实 Root、通知、模型、网络均没有实现或调用。

任务配置采用根从 v3 实际导出的 `fixture-data.js`（根拥有），`window.uxTaskFixtures` 为22任务名称、schema、values、common、steps的唯一数据源。renderer重新实现 number/text/textarea、单选按钮、多选按钮；保存校验schema显式required/min/max/step及选项约束，不重新造业务范围、来源或步骤。资源影响只放配置正文，列表不重复。优先级修改不改已排队项的快照。默认当前步骤原文为“打开每日奖励”；daily计划为常用，但与唯一当前plan去重，不作为另一条候选。原规则完整链接保留，探索稿不改变旧包合同。没有 localStorage、请求或秘密数据。

球可拖动，只是沿用既有拖动能力；没有自动吸边、自动躲避或新手势。球锚点分横竖屏记忆。展开面板以该锚点为参考进行视口fit：下面空间不足时放到球上方，并钳制左右与顶部边界；小球坐标不改变。标题与当前行不收缩，剩余空间由候选内部滚动。这不是自动吸边、游戏场景避让或新增手势。

## 入口与 API

URL 参数：

- `?page=home|tasks|game`
- `orientation=portrait|landscape`
- `fixture=running|paused|pausing|hold|idle|unknown`
- `layer=ball|quick|common`

例如 `app.html?page=home&orientation=landscape`，`app.html?page=game&orientation=landscape&layer=common`。设备外控件切状态，不混入产品界面。

`window.uxPrototype`：

| API | 作用 |
| --- | --- |
| `getState()` | 脱离引用的共享 UI 夹具副本，含 current/queue/tasks/drafts/层级 |
| `setPage('home'|'tasks'|'game')` | 切本轮页面 |
| `setOrientation('portrait'|'landscape')` | 切方向，保留夹具与草稿 |
| `setFixture(value)` | 重新种入一组演示运行状态，不代表正式用户功能 |
| `getManifest()` | 工作台、任务、悬浮、恢复态与22任务配置清单 |
| `setOverlayLayer('ball'|'quick'|'common')` | 切三层 |
| `setScene('courtyard'|'dungeon'|'shop'|'souls'|'unknown')` | 场景候选夹具 |
| `selectTask(id)` / `saveTask(id)` | 进入及保存原schema字段 |
| `enqueue(id, kind='task')` | 展示提交，可传已有 plan 引用 |
| `pause()` / `stop()` / `remove(runId)` | 请求态与结果的 UI 演示 |
| `recover('continue'|'restart')` | 恢复选择 UI 演示 |

## 本地检查与交还

Node 语法检查通过；惰性 DOM 测试覆盖三页面双方向、层级渲染、选中保留、顶层引用去重、暂停恢复、无当前 hold、移除继续、停止保留队列。子 agent 未启动浏览器、未声称看到了真实渲染；主 agent负责同夹具新旧对比、短屏可见高度、长名/滚动/命中区与真实截图后打回。设计效果是否更好要靠这些对比，不靠累计检查数。

## 首轮实际截图后的复改

按根独立截图反馈：账号禁选择只限制操作，身份文字不随disabled变淡；底部当前任务主名16px/600，phase与来源放次文，避免队列压过当前；悬浮当前次文用真实current stepLabel，不将整计划0/6误标成当前task步骤数；行尾禁用文案用“队列中”，不另加badge。分类虚构字段已删除，全面切换根导出的原schema、steps与values。

## 最终操作可达性复改

竖屏任务详情保存置于路由顶栏右侧，版本入口仅保留任务中心列表；删除详情正文空标题栏，长表单到底不用回滚找保存。横屏配置pane的标题/保存sticky固定于pane顶。工作台底部执行条用紧凑“移除”文字替代X，避免误解为收起；其真实移除语义不改，队列行X和悬浮停止保留，不添确认。

本轮不采用跨所有页面的常驻执行dock：执行管理留在工作台，任务列表仅控制该顶层实体，避免任务/计划/设置重复叠一层控制。这是明确取舍，不是漏铺页面。

最终移动触达复改仅涉及悬浮CSS：暂停/停止及其他图标控制透明命中48px，当前行gap8px，图标20px不变。保留原292px快捷面板和横屏430px常用面板宽度，不靠缩文字抵消命中空间，也不增加控件。

拖动边界复改：球靠底展开时不再将弹层压到仅剩95px；菜单按已知视口与宽度计算可用高度，必要上翻及左右边界约束。该布局函数只投影位置，不写回球的anchor，不改变运行或层级。

横屏最后空间复改：周期按钮组移入app-top标题与版本之间，不增加顶栏高度；正文只保留一行六分类tabs。列表和配置pane省去一行约40px筛选区。竖屏仍是分类后周期，选中与筛选行为不变；横屏pane保存继续sticky。
