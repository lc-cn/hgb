# v5 明暗与玻璃材质：独立验收关注

本轮目标是把已确认的布局与流程应用为黑白灰主体的明暗主题，按钮使用液态玻璃；默认跟随系统，用户可手动选择。黑白灰是主色，运行／信息用蓝、成功用绿、warning／未知用琥珀、失败用红、更新用红点，仍保留文字／图标等非色提示。主题切换仅放设置右上角紧凑的「系统／浅色／深色」三按钮，不新增独立外观页或外观列表入口。不是新一轮系统建设或业务扩展。本清单只定义验收，目前不宣称已通过。

依据：用户本轮确认优先于 [`mobile-uiux-pro-max`](/Users/liuchunlang/.codex/skills/mobile-uiux-pro-max/SKILL.md) 的默认风格。已读该 skill 的 `rules/system/dark-mode.md`、`rules/system/platform-conventions.md`、`prompts/audit-screen.md`。采用 DRK-001/002/004/008/010/011 与可读性、平台交互原则；不把「Android 必须无玻璃／动态壁纸取色」作为限制。黑白灰不意味着通过颜色反相生成暗色，也不意味着把所有状态画成无法区分的灰块。

产品仍是 Android 工具 App。本轮交付为 HTML/CSS/JS 设计模拟：浏览器中的像素、系统主题媒体查询、模糊效果和本地主题偏好，均不能证明原生 Android 的 dp、系统栏、输入法、返回手势或真实材质 API 已实现。

## 七个必须真实检查的点

| 关注 | 最少但有效的验证 | 不足以证明通过的材料 |
| --- | --- | --- |
| **1. 系统／手动主题闭环**（DRK-008/011） | 清除本稿主题偏好：系统亮→亮、系统暗→暗；跟随模式下切系统立即正确变化。从设置右上角三按钮手动亮／暗后，系统变化不覆盖选择；改回跟随后重新响应；设置列表无独立外观页入口。跨新 UX、完整流程、开发者入口及返回时选择一致；刷新或首次加载不先露明显错误主题。保留当前页面、草稿、滚动和执行展示状态。 | 仅有三个按钮；仅切 `data-theme` 截图；通过评审工具强制暗色，却未验证产品主题入口；仅最后一帧正确。 |
| **2. 两套真实语义色，不漏旧稿硬编码**（DRK-001/002/009/010/012） | 源码确认共享语义 token 的明暗映射；浏览器检查工作台、任务列表／长表单、版本、模型、通知／历史、网络、账号、开发授权、动作／schema、JSON、调试／诊断、上传及弹层。每个代表页面两主题均看；状态栏／导航／输入／禁用／选中／错误／toast／滚动区无遗留绿调或意外白块。游戏画面和识别截图可保持内容本色，覆盖其上的控件须适配。 | 只有首页暗色；只有外层背景变黑；CSS 有 dark selector；把游戏或内容图片也反相。 |
| **3. 对比度检查最终合成结果**（DRK-004；WCAG AA） | 正常文字至少 4.5:1、大字至少 3:1，必要图标和控件边界至少 3:1。分别核查标题、次文、输入值、按钮文字、选中／未选中、提示与浮层。玻璃需在实际浅／暗／高变化底图上检查，记录前景色、最终合成背景及计算方式；至少覆盖亮暗各一种最不利背景。当前账号等有用信息即便所在控件禁用，仍能读懂。 | 从透明 RGBA 与主题基色直接算一次；只用 token 两两组合；只看平坦白底／黑底；以「禁用可豁免」解释关键信息消失。 |
| **4. 玻璃是控制层材质，不是内容蒙雾**（用户定制；PLAT-005 的可读性原则） | 同底图对照可见按钮材质：适量透底、边缘／高光／深浅层次，亮暗各自成立；短标签与图标仍清楚。按压、选中、禁用有可辨差异。任务名称、JSON、规则文字、输入表单不因套玻璃而蒙雾。对真实游戏背景看悬浮控制，不能只展示静态灰色样板。 | 仅调透明度或画一条白边即称已达到液态玻璃；仅源码出现 `backdrop-filter`；把所有卡片和正文层一起模糊；以高光遮住文字。无需新增折射 shader 或装饰动画证明材质。 |
| **5. 无模糊／减少透明／减少动效时仍能操作**（PLAT-005；skill 降级原则） | 禁用 `backdrop-filter` 支持或以评审夹具走 fallback，按钮应有足够实体底色、边界和对比；减少透明偏好（浏览器支持时）与不支持该媒体查询的环境都不能成为不可见控件。若存在材质动画，减少动效时停用非必要动画。降级后再点实际按钮、打开弹层，确认不是仅替换截图。 | 只存在 `@supports`；不透明 fallback 仍依赖失效的模糊；用 outside-frame 注入假装证明真实 OS 偏好已联动。不得为验收额外增加产品内透明度开关。 |
| **6. 中性主体配语义色，仍能辨状态与操作**（skill a11y；原交互约定） | 同一页面并排比较：常用／非常用、入队／队列中／当前暂停、选中／未选中、忙碌／可点、失败／未知／成功。主体保持中性，运行／信息蓝、成功绿、warning／未知琥珀、失败红、更新红点正确映射；名称、形状、图标、选中标记或文本同时承担语义，不只靠颜色。点击反馈不导致布局跳动，原来的禁用与安全阻断仍有效。 | 因去色而去掉状态文字；所有按钮同强度；重新加入大段帮助说明弥补状态不清；把未知用成功样式表达。 |
| **7. 材质不倒退已经收敛的 Android 操作与布局**（PLAT-002/003/010/011/015；既有约定） | 412×860 与 900×412 两主题检查核心页：新 UX 的紧凑导航／队列／dock、固定保存、单行分类、三层悬浮及 viewport-fit仍成立；完整稿的版本极简行、表单按钮组、时间日期输入、路由栏操作、开发权限路径保留。按钮视觉可小，真实命中区保持可用：普通／悬浮核心控制沿用约48px透明目标，邻接暂停／停止保留间隔；不被高光层、伪元素、模糊层截获点击。实际拖球到底展开、候选滚到底仍能控制当前任务。 | 为做玻璃把 Android 导航替换成新的 iOS 页面体系；加装饰导致短横屏控制被挤出；把 px 检查写成 Android 48dp 已验证；凭截图猜测命中区。 |

## 验证边界与最小证据

静态检查负责发现 token 绕过、遗留颜色、缺少 fallback、事件监听／偏好优先级、伪元素拦截与状态样式遗漏。skill validators 可运行并保留原始输出，但必须说明它们对本项目 HTML/CSS/JS 的实际解析覆盖。把 `--help` 当输入路径仍返回满分，或者扫描不到组件，说明没有有效验证；**不输出可误导的综合质量分，不以零告警／100 分签收**。

浏览器证据由根 agent 负责，最少保留：

- 一条主题链路记录：首次跟随、系统变化、两种手动覆盖、回到跟随、跨入口／刷新；不只截静态两主题。
- 同夹具、同滚动位置的亮暗对照：新 UX 工作台／任务／长配置、悬浮快捷／常用；完整稿代表性表单／版本／通知／历史；开发授权／制作／调试／发布。页面清单说明哪些共享组件覆盖，不能只报截图数量。
- 少量关键的最终对比度样本，包含玻璃实际合成背景；unsupported blur／减少透明／减少动效分支的结果及局限。
- 固定保存、右滑／暂停／停止控件、底部展开悬浮及长表单的真实操作复验；不重新跑与材质无关的全部业务算法测试。

只签收本轮主题与材质在设计模拟中的表现。真实 Android 系统偏好、原生系统栏／选择器、屏幕密度、触摸设备、GPU 模糊性能、通知／游戏／GitHub能力继续明确为未验证。保持此前功能边界，不新增高对比主题、AMOLED选项、RTL、多语言、平板折叠屏、强制确认弹窗或七类业务状态来凑 skill 清单。
