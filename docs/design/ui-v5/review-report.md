# 明暗主题与彩色图标设计验收

本轮交付是可点击的 HTML 设计模拟，Android 为目标平台。主色为黑白灰，图标允许蓝、紫、橙、青、玫红和金色；运行蓝、成功绿、警告琥珀、失败红保持状态含义。按钮以 CSS 模拟透光、反射和内沿高光，非原生 Liquid Glass 实现。

## 本轮落实

- 默认跟随系统；设置标题右侧直接选择“系统／浅色／深色”。没有独立外观页面或设置列表入口。手动选择更新 URL 与本地外观偏好，刷新及跨页面保持一致。
- 图标采用统一线条形状，使用带透明度的彩色图标与小面积色底。普通图标不透明度 82%，警示等状态图标 92%；文字和按钮本身不随图标淡化。任务中心紫、计划橙、历史青、设置玫红、常用星标金；设置入口按用途区分颜色。选中按钮使用适配反色背景的图标颜色，禁用保持灰色。没有增加说明文字、菜单或业务操作。
- 共享主题 tokens 与按钮材质层覆盖主稿、完整流程和开发者工具。玻璃按钮统一普通、选中、悬停、按压、禁用与焦点状态；减少透明度或不支持背景模糊时回退实色，减少动效时关闭反馈位移和过渡。
- 主稿保留上一轮的队列优先工作台、底部当前执行条、横屏导航栏与任务配置双栏。任务/计划的入队、常用、暂停/恢复等既定语义不变。悬浮球保持球、快捷控制、常用列表三层。

## 来源与边界

使用指定的 [mobile-uiux-pro-max 技能](/Users/liuchunlang/.codex/skills/mobile-uiux-pro-max/SKILL.md)，根据 Android 交互、图标、明暗主题和 token 规则检查。用户指定的玻璃材质优先于技能的默认外观建议。

`app.*` 来自上一轮已调整结构的核心 UX；`full.*` 和 `developer.*` 在保留既有完整业务流程的基础上接入共享主题与图标体系，不能将它们描述成所有页面均重新设计。完整流程保留部分原有尺寸定义，未宣称全部几何数值已 token 化。

三组页面各自使用本地 fixture 运行时，没有连接生产执行器。仅外观偏好持久保存；游戏控制、账号登录态、队列、定时计划、模型、代理、通知、GitHub 权限、调试和发布均为模拟，无真实服务调用或 Release 发布。

## 验证证据

- `evidence/theme-journeys.json`：实际浏览器验证系统默认、手动切换、刷新、系统变化、跨页面、表单草稿、开发者未知结果及权限状态保持；检查明暗横竖屏布局。
- `evidence/composite-contrast.json`：在实际合成背景中采样按钮文字与图标，包含选中、悬停、按压和实色回退。精确结果以文件为准。强制启用不支持模糊的 CSS 分支仅验证层叠逻辑，不代表真实旧设备测试。
- `evidence/icon-colors.json`：彩色图标在两主题的普通背景、色底、强色按钮和禁用状态的专项复核。
- `evidence/screens.json`：正常 GPU 浏览器导出的明暗、横竖屏截图。
- `evidence/skill-audit.json`：技能静态检查，仍有悬浮定位的 left/right RTL 提示。该工具对 HTML/CSS 的检查有限，分数不作为可用性或无障碍合规证明。
- `evidence/delivery-manifest.json`：最终源文件和截图摘要。

浏览器检查采用正常 GPU 合成；禁用 GPU 的 headless 环境曾出现模糊按钮合成异常，未将该环境问题写成产品补丁。未验证 Android 真机、模拟器权限、GPU 帧率、电量、系统后台存活、动态字号和完整 RTL。设计预览验收不代表真实应用可发布。
