# 区域关联与图形状态动作提案

2026-11-18，基于 `06312eb` 和[区域／图形状态离线实验](../development/build-evidence/region-state/README.md)。**待用户确认，未实现。** 当前 App 不能加载下文字段；示例只说明合同形态，不是可安装任务或游戏默认值。

## 要解决的缺口

一次免费领取的实际画面说明：仅凭文字无法安全判断每日礼包状态。

- “已领取”红章被 OCR 读成“领取”，不能用文字分类区分可领与已领。
- 整图 OCR 没有检出付费价格“1”，“没读到价格”不能当成免费。
- 现有 `screen.readText`／`classifyText`／`locateText` 都只针对整帧文字，不知道一个词属于哪个商品。

离线实验在真机上测得：锚点文字可以唯一定位商品卡片和详情列，并推出 ROI；ROI 内的魂玉图标模板能区分有价格和无价格（本组可分，样本少）；红色像素计数不能区分已领红章和红色道具图；红章模板没有独立正例。

## 建议新增的三类能力

都沿用现有动作合同：输入必须由任务版本明确声明，引用当前输入阶段内本步骤的前序观察，输出只在本次尝试内有效，输入后旧观察不可复用。

### 1. `screen.deriveRegion`：从锚点推出区域

- 输入：`target`（`screen.locateText` 输出的锚点）、`offset`（相对锚点水平中心和底边的 `dx`、`dy`、`width`、`height`）、`referenceSize`（偏移所依据的截图宽高）。
- 输出：`region`，绑定到与锚点相同的观察。
- 按当前帧与 `referenceSize` 的比例缩放；区域超出画面直接判为无法确认，不截断。
- 锚点本身沿用 `locateText` 的唯一性规则：零个或多个候选都不选。

实验依据：4帧锚点均唯一，推出的 ROI 与人工框 IoU 0.79–0.92。**跨分辨率缩放尚未验证。**

### 2. 区域限定的现有文字动作

`screen.readText` 增加可选 `region` 输入（必须来自同一观察的 `deriveRegion`），只识别区域内文字。`classifyText`／`locateText`／`expectText` 不变，引用这次区域读取即可。

实验依据：ROI 内“领取”“免费”均正确，价格“1”在 ROI 内被读出；但同时读出了图标噪声，变暗价格被读成“918”“930”。所以**价格数值不作为免费／付费的判断依据**，只作辅助记录。

### 3. `screen.matchImage` 与 `screen.classifyRegion`

- `screen.matchImage`：输入 `region`、`template`（任务版本中声明的 PNG 资源，走现有资源摘要和使用租约）、`minimumScore`；输出 `matched` 和 `score`。使用 Maa TemplateMatch（归一化相关系数），在现有隔离识别子进程中运行。
- `screen.classifyRegion`：在 `classifyText` 的基础上，每个状态可同时声明“必须有的文字”“必须有的图像”“必须没有的图像”。只有恰好一个状态的全部条件都满足才输出该状态；零个或多个满足、任一证据识别失败，都保持无法确认，不用“否则”分支猜测。

每日礼包按钮的状态示例（示例值，不是默认）：

| 状态 | 条件 |
| --- | --- |
| `claimable` | 区域内有文字“领取”，且没有魂玉图标 |
| `paid` | 区域内有魂玉图标 |

`claimable` 才进入点击分支；`paid` 不点击，任务以“今日免费已不可领”结束；其他情况为无法确认。领取后的“已领取”判断目前**没有可用证据**：红章模板只有同帧正例，颜色计数已证明不可分。领取后的核对暂时只能依赖“奖励弹窗文字”和“列表按钮变为 `paid`”，红章证据需要另外采样后再决定。

**不建议**现在加入颜色计数动作：实验中红章列 3855 像素，红包类道具图高达 8258。

## 需要特别处理的风险

- **模拟器崩溃**：Apple Silicon 宿主上的 AVD 声称支持 `sve2` 但实际不支持，OpenCV 模板匹配会 SIGILL 终止进程。真机（不含 SVE）正常。生产实现必须把模板匹配留在现有识别子进程，崩溃按观察失败处理；本机 AVD 不能用来测模板匹配路径。可以考虑在启动识别前检查 CPU 特性，不支持时明确报错，但这要求另行验证。Windows 模拟器尚无证据。
- **样本不足**：魂玉模板的不同正例只有10个、负例2个，同一设备、同一主题、同一天。变暗状态的得分（0.55）离负例最高值（0.278）不远。正式阈值必须在更多采样后确定，任务资源中的阈值要标明来源。
- **模板资源**：模板图来自游戏截图裁剪，属于任务版本资源，不打包进 APK；更换主题或版本可能需要新模板。

## 确认后的实施顺序

1. core：新增 `region` 输出类型、三个动作合同与静态校验（引用来源、同一观察、资源声明、偏移和阈值范围）。
2. vision：在现有子进程协议中增加 TemplateMatch 和 ROI 参数；崩溃、超时与现有 OCR 一样处理。
3. app：`ScreenActions` 接入，执行记录保存区域、得分与所用模板摘要。
4. 测试：核心单元测试；真机执行静态帧对照；模拟器只覆盖不触发模板匹配的路径。
5. 再请求授权采集“已领取”第二个样本（例如次日领取后的详情页），之后才制作每日礼包任务。

## 需要用户决定

- 是否按上述三类能力实施（或只做 1、2，暂缓图像匹配）。
- 是否批准后续在真机上采集更多状态样本：次日领取后的详情／列表，以及不同主题或活动期的商店页。
