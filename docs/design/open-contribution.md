# 对外开放贡献：人人能写任务，提交即 PR

日期：2026-11-21（审查后修订）。状态：已确认（2026-11-21），按四步实施，页面见设计稿“开放贡献”一组。建立在开发工作台（`developer-workbench.md`、`developer-workbench-tech.md`）之上；确认后，同步修改这两份文档中关于开发者资格、发布出口和单一任务包的部分。

## 目标与边界

- 任何护肝宝用户都能用工作台给自己写任务、在自己手机上试跑。
- 写好的任务一键“提交”，服务端在任务仓库代建 PR，附上机器能做完的检查；维护者审核合入。
- 合入的任务先进“社区频道”，用户自愿开启；稳定后升到正式频道。
- 社区任务做不成坏事：不付费、不毁资产、不替用户发言、不动账号。靠 App 里的硬护栏保证，不靠审核。

不做：任意代码插件；匿名提交；对社区任务收费。

## 分四步开放（每步都做完，不留“二期”）

| 步 | 开放什么 | 前提 |
| --- | --- | --- |
| 1 自用 | 登录即可：草稿、样本、模板、在自己手机上试跑与探测；App 里“悬浮球开发工具”开关（默认关） | 两道门槛分开；配额 |
| 2 提交 | 一键提交成 PR；看审核意见、改了再提交 | 仓库存源、护栏上线、试跑证据落库 |
| 3 社区频道 | 合入的任务进社区包；App 可开关；停用名单 | 健康度统计 |
| 4 分级 | 新人、可信、维护者 | 足够的合入与运行记录 |

## 两道门槛

| 角色 | 能做什么 | 怎么认定 |
| --- | --- | --- |
| 作者 | 草稿、样本、模板、检查、在**自己的**手机上试跑和探测 | 已登录 |
| 作者提交时 | 用自己的 GitHub 账号 fork 并开 PR | 第一次提交时同意贡献协议，并另行授权 GitHub（`public_repo`） |
| 维护者 | 审核、合入、打回；发布；升降频道；停用；改游戏设置；新增游戏 | GitHub 账号对任务仓库有写权限（沿用现有判断） |

现在所有 `/api/dev` 接口都走同一个“写权限”判断，要拆成这两道。试跑、探测、采样仍然只能发到本人名下、在线且空闲的手机上（现状已如此，保持）。

## 游戏设置与任务分开存，贡献者只能改任务

护栏的数据（危险画面、限额、目标应用）如果和任务放在一起，一个 PR 就能把护栏改掉。所以拆开：

```text
games/<游戏>/game.json          游戏设置：目标应用与包名、视觉配置、资源表、危险画面、限额、账号识别与切换
games/<游戏>/states/*.json      状态库（普通状态）
games/<游戏>/snippets/*.json    片段库
games/<游戏>/tasks/<任务>.json  每个任务一个文件，带作者、负责人、频道、消耗声明
games/<游戏>/templates/*.png    模板
```

- `game.json`、账号识别与切换任务、新游戏：只有维护者能改。仓库用 CODEOWNERS 加主干规则集强制（主干只接受审核通过的 PR），检查接口也会拒收碰到这些文件的提交。
- 每个文件规范化排版（一行一项、键排序），两个 PR 改不同任务时不冲突。紧凑写法只作为打包产物。
- 共享的片段、状态被改时，所有用到它们的任务都算作有改动。

## 护栏：App 执行时强制，任务里写什么都绕不过

1. **只操作已知游戏**：App 内置游戏包名白名单（随 App 发布，不随任务包）。启动和每一次输入前，都核对这一帧的前台包名；不在白名单里就不输入。
2. **危险画面守卫**：危险画面分四类，写在维护者的 `game.json` 里：
   - 付费：充值、商城购买确认、魂玉支付；
   - 毁资产：升星喂卡、出售或分解御魂；
   - 社交：发言、邀请、公开、删好友、退寮；
   - 账号：改名、绑定、登出。

   拦截规则：
   - 每一种输入（点、点区域、滑动、拖动、长按、返回）送出前，用它本来就要重截的那一帧判一次。
   - 送出后再判一次。输入前命中就拒绝输入，输入后才出现就立刻停下；两种情况步骤都记为“未知”，并提示用户。
   - 识别失败或画面不是游戏，一律不输入。
   - 这会给每次输入多一次模板或文字判断，计入等页面代价估算（tech §5.4）。
3. **点空白要验空**：社区任务的“点区域”必须开启“区域内有文字就不点”，除非这个区域是维护者在 `game.json` 里登记过的安全区域。
4. **动作白名单**：能力合同上标 `community: true` 的才能用于社区任务。启动其他应用、将来的文字输入等，一律不在白名单里。
5. **运行限额**：单次运行的最长时长和最多输入次数由 `game.json` 规定，超出即停。

**消耗声明只是标签**：任务写明会消耗什么（体力、勾玉、金币、友情点……），安装和首次运行时展示给用户。声明消耗魂玉或付费货币的社区任务，检查接口拒收；但“不付费”真正靠的是上面的守卫，不是声明。检查接口还会提示可疑的写法，例如在商城页找字、读货币数字。

**私装的范围**：作者在自己手机上试跑、私下导入的任务，用的是自己草稿里的设置，可能改过护栏。那只影响作者自己的账号；凡是发给其他用户的包，都只用维护者的 `game.json`。

## 提交流程

1. 作者在工作台点“提交”，选这次改了哪些任务，写一句说明，可附带打码截图（见“审核”）。
2. 服务端在**主干某个提交**的基础上算改动（草稿记下基于主干的哪个提交，由服务端记录，不由客户端填）：
   - 按节点列出新增、修改、删除的任务、步骤、片段、状态，以及受影响的任务。
   - **检查报告**：读包校验，护栏（不碰 `game.json`，消耗声明合法，动作在白名单内，点区域都开了验空），素材体积与新增模板，隐私（模板不碰玩家信息区域，样本不进 PR），最低 App 版本。
   - **试跑证据**：每个受影响的任务，都要有一次**整任务**试跑完成，且试跑时的编译摘要（任务、片段、状态合起来的摘要）与这次提交一致。证据由作者自己的手机上报，标为“自报”。
3. 主干有新合入时，服务端按节点做三方合并；有冲突就在“我的提交”里列出，作者处理后再提交。
4. **用作者自己的 GitHub 账号**：服务端拿作者授权的令牌，把任务仓库 fork 到作者名下，在 fork 的分支 `contrib/<短名>` 上提交改动的 `tasks/`、`states/`、`snippets/`、`templates/` 文件，再向主仓库开 PR，正文是检查报告。
   - 令牌只在提交时请求 `public_repo` 授权，加密存到会话结束，不长期保存。
   - PR 就是作者本人发的，身份、追责都由 GitHub 承担。
   - 来自 fork 的 PR 跑 CI 时拿不到仓库密钥。
   - 不需要能写主仓库的机器人账号。
   - 作者写的说明仍然去掉链接和 @。
5. 作者再次提交时推到同一分支，已有的审核同意自动作废，维护者需要重新审。

## 审核

- 维护者在工作台“审核”页处理提交：按节点看改动，与主干并排；看检查报告、试跑证据和打码截图。
- **在自己手机上试跑这次提交**：从提交快照编译，只发到维护者自己的手机。页面会提示：这会用维护者自己的游戏账号运行未合入的步骤。
- 合入只合入审核时看到的那个提交；之后的推送不算。
- 有这些改动时一律逐步审核，可信作者也不例外：新的或改动的点区域、滑动、长按、拖动，新的状态，改了共享片段。其余改动，可信作者走快速审核。
- 合入后先攒着，按计划批量发布，不是每合一个就发一版。
- 维护者人少时：提交超过 14 天没人审，作者会收到提醒；作者 30 天不回复，提交自动关闭。

## 发布、频道与停用

- 同一个版本里放两个包：
  - `task-bundle.json`：只含正式任务；
  - `task-bundle-community.json`：正式任务加社区任务。

  App 按“社区任务”开关选包（开关默认关，开启时提示风险）。旧 App 只认第一个包，不受影响。
- 发布从主干的某个提交打包，模板取自仓库。维护者自己的改动也走 PR（可以自动合入），保证主干与发布一致。
- **停用名单**存在服务端，按任务和编译摘要登记，也可以一键“停用全部社区任务”。服务端派作业时检查它，App 本机运行前也检查它。生效不必发新版本，总开关和“7 天没人修就撤下”都靠它。
- 关闭开关或任务被停用后，计划里引用它的条目标为“已停用”并通知用户，不会默默失效。
- 健康度统计按任务的编译摘要（不按版本标签）、按天汇总服务端派发的作业结果：
  - 失败率不算取消和跳过；守卫命中单独计数。
  - 至少要有 10 个不同的游戏账号在用，且不含作者自己的账号。
  - 设备上报游戏版本号，游戏一更新就能对上失败率的变化。

  升级与撤下：
  - 连续 14 天、至少 10 个账号、失败率低于 5%：提示维护者可以升为正式。
  - 游戏更新后失败率超过 30%：标“可能失效”并通知负责人，7 天没人修就进停用名单。
- 每个任务有**负责人**，默认是作者，可以转交。

## 分级与配额

| 等级 | 条件 | 待遇 |
| --- | --- | --- |
| 新人 | 登录即是 | 每周 5 个新提交；样本总量 500 MB；逐步审核 |
| 可信 | 合入不少于 5 个，加入超过 60 天，最近 60 天没有任务被撤下或守卫命中 | 每周 30 个新提交；样本 2 GB；部分改动快速审核 |
| 维护者 | 由维护者邀请 | 任务仓库写权限 |

- 所有作者都有频率限制：检查接口每分钟最多 20 次；采样、试跑、提交各有上限；建 PR 全局排队。推到已有 PR 不算新提交，但同样限频。
- 样本超额时，先删最旧的；账号注销时，样本、模板、草稿一并删除。
- 出过事的作者（任务因守卫命中被撤下）降回新人。

## 隐私

- 样本只属于作者，保存 180 天，永不进 PR、不进任何包。
- 打码截图由作者自愿附上：玩家信息区域强制打码，只随提交存在服务端，只给审核者看，不进 PR。
- PR 里只放任务源和小模板。试跑证据只保留步骤、动作、结果和用时，不含配置值、原因文字、设备标识。
- “确认是游戏界面文字”由作者自行确认，审核时要看。
- PR 由作者自己的 GitHub 账号发出，公开可见；提交前提示这一点。

## 合规

自动化本身触碰游戏用户协议。开放平台会把风险从“个人自用”放大到“提供工具”。上线前要具备：

- 贡献协议：许可方式、合入后的使用权、仓库许可证；
- 投诉下架渠道；
- 社区频道的风险说明，用户开启时需逐人确认；
- 服务端总开关：可以关闭注册使用工作台、提交和社区频道。停发已安装的社区任务，靠停用名单。

是否开放、何时开放由你决定。

## 数据与接口（概要）

| 对象 | 内容 |
| --- | --- |
| `game.json` | 目标与包名、视觉配置、资源表（标出付费货币）、危险画面（四类）、安全区域、限额 |
| 任务文件 | 任务定义，加 `author`、`owner`、`channel`、`consumes` |
| 能力合同 | `community: Boolean` |
| `dev_contributions` | 作者、游戏、基于主干的提交、编译摘要、改动摘要、检查报告、打码截图、分支、PR 号、审核时的提交、状态、意见 |
| `dev_trials` | 作者、手机、App 版本、编译摘要、是否整任务、结果、时间 |
| `task_blocklist` | 游戏、任务、编译摘要（或“全部社区”）、原因、时间 |
| `task_health` | 游戏、任务、编译摘要、日期、完成 / 失败 / 未知 / 守卫命中次数、账号数 |

接口：
- 作者：`POST /api/dev/github/authorize`（提交前授权）、`POST /api/dev/contributions`、`GET /api/dev/contributions`（我的提交）。
- 维护者：
  - `GET /api/dev/reviews`、`POST /api/dev/reviews/{id}`（合入或打回）；
  - `POST /api/dev/reviews/{id}/trial`（试跑这次提交）；
  - `PUT /api/dev/blocklist`；
  - `GET /api/dev/health/{游戏}`。
- 发布接口改为从主干的某个提交打包，产出两个包。

## 页面（设计稿“开放贡献”一组）

1. 作者首页：草稿任务、我的提交入口，以及配额。
2. 提交页：选任务、写说明、附打码截图；检查报告与试跑证据，有一项不过就不能提交。
3. 我的提交：状态、审核意见，以及与主干的冲突。
4. 审核页（维护者）：列表与详情（按节点的改动、报告、证据、截图、在自己手机上试跑、合入或打回）。
5. 游戏设置补充（维护者）：危险画面四类、安全区域、限额。
6. App：任务库的“社区任务”开关（带风险确认）；任务卡标出“社区 · 作者 · 会消耗”；守卫拦截时的提示。

## 验收

1. 新用户不需要 GitHub，就能写任务并在自己手机上试跑；不能发到别人的手机上。
2. 提交生成 PR，正文是检查报告；再次提交时更新同一 PR，原有的同意作废；合入只合入审核时的那个提交。
3. 碰到 `game.json`、账号任务或新游戏的提交被拒。
4. 下面这些输入都被守卫拦下：
   - 在四类危险画面上，点空白偏移、滑动、零位移拖动、长按、返回；
   - 前台是别的应用时的任何输入；
   - 识别失败时的任何输入。
5. PR 来自作者的 fork；主干只接受审核通过的 PR；发布凭据只在服务端、只给维护者用。
6. 试跑证据在服务端重启后仍在；改任务、或改它用到的片段和状态后，证据作废。
7. 停用名单或总开关一设，下次派作业就停，不用发版；计划里的条目标为“已停用”。
8. 旧 App 不受影响；开关社区任务时换包，设置保留。
9. 配额与限频生效。
10. PR 里没有样本、配置值、识别文字、设备标识；审核者能看到打码截图。
11. 健康度不含作者自己的账号，也不含取消和跳过；账号数不够时不给升级建议。
12. 维护者试跑提交时，只在自己手机上跑审核时的快照。

## 已确认（2026-11-21）

1. 任务仓库改为存源，并按游戏设置、状态、片段、任务、模板拆成文件；游戏设置与账号任务只由维护者改。
2. 作者门槛为“已登录并接受协议”，GitHub 可选；维护者仍按仓库写权限认定。
3. 社区任务一律不得付费、毁资产、发言、动账号，由 App 护栏强制。
4. 社区频道默认关闭，开启时需要逐人确认风险。
5. 提交走作者自己的 GitHub 账号：fork 任务仓库并开 PR，第一次提交时授权 `public_repo`，令牌不长期保存；仓库加主干保护规则（我会写好设置步骤）。
6. 分级、配额、健康度阈值按文中数字起步，上线后再调。
