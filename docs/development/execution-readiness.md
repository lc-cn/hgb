# 步骤启动条件

2026-11-17。此处补齐原运行宿主的启动边界，沿用唯一执行器，不新增任务状态机或调度器。

## 已复现的问题与归属

在专用模拟器的独立数据库中安装完整文字观察任务，随后断开助手无障碍连接再入队。原宿主只核对目标／账号条件，直接创建屏幕工作器；第一次读取因无连接而产生“未连接无障碍服务，未取得画面”的未知结果，队列进入结果核对状态。它发生在任何输入之前，是缺少启动条件检查。不能把工作器已经开始后的错误改成成功，也不能自动重试可能有输入的程序来补偿。

回归断言要求：入队成功但尚未创建工作器；当前项与版本引用保留；没有业务未知／输入记录；重新连接后由真实服务事件重新检查，完成实际截图／模型 OCR，最后释放引用。修复前失败记录和修复后设备结果见 [start-readiness](build-evidence/start-readiness/README.md)。

## 条件与所有权

`ExecutionRuntime` 在读取该轮锁定版本并核对目标／账号后，调用 `ExecutionStartReadiness`，通过后才创建工作器。结果分为可开始、已知条件不满足、条件暂无法确认。后两者都保留待开始的尝试并展示等待原因；查询异常不冒充“目标肯定在后台”，也不成为已执行任务的失败或业务未知。版本读取损坏／存储故障仍走原来的内容错误／存储故障路径。

Android 实现按当前步骤的 APK 动作合同确定依赖：纯等待等工具步骤不要求无障碍；观察或输入步骤要求服务已连接、默认屏幕亮起、焦点应用属于锁定版本的目标包集合。它不截屏、不 OCR，不推断账号，不启动游戏或解锁设备。账号条件仍由独立身份核对端口负责；匿名目标不会变成绕过游戏账号核对的途径。

服务连接、应用焦点、方向及屏幕电源变化仅是条件失效事件，由同一宿主重新查询。没有轮询计时器、业务重试、自动启动或新增通知规则。等待期间用户仍可暂停、停止或移除；暂停／停止保留人工接管，移除当前项后按原规则选择下一项。旧查询通过原票据和绑定 Job 身份核对，迟到结果不能复活已移除／暂停的尝试。

安全无输入恢复也经过同一启动条件。真正结果未知仍保留原暂停边界，普通焦点／服务事件不能清除它。已有执行中的程序继续使用原截图／手势许可、前台校验、独立静默与业务结果核对。启动检查只是一个时点的前提，不能保证之后屏幕或权限不变化；开始后的不确定结果仍按原规则处理。

## Android 合同与界面

使用输入焦点的应用窗口查询包身份，避免把最近触摸的悬浮窗口当成目标。节点查询放在 IO，返回前核对服务连接代次；所有查询所得节点／窗口按支持版本的 API 释放。此选择依据 [AccessibilityWindowInfo](https://developer.android.com/reference/android/view/accessibility/AccessibilityWindowInfo) 的 `isFocused`／`isActive` 区分及 [AccessibilityService](https://developer.android.com/reference/android/accessibilityservice/AccessibilityService) 的窗口接口合同。

服务 XML 增加 `flagRetrieveInteractiveWindows` 和 `typeWindowsChanged`，以取得应用焦点窗口及焦点变化；原有 `canRetrieveWindowContent` 保留。依据 [AccessibilityServiceInfo](https://developer.android.com/reference/android/accessibilityservice/AccessibilityServiceInfo) 的窗口检索要求。没有新增 Manifest 危险权限、依赖或 Room 表。显示监听器只把默认屏幕电源状态变化作为失效事件，服务解绑／销毁时注销；刷新率变化不反复唤醒任务检查。

工作台在当前队列行展示等待原因，底部和任务行显示“等待中”；悬浮面板沿用同一状态。等待是普通文字，业务未知和存储异常仍用错误展示。继续使用现有暂停按钮及右滑移除，不添加处理向导或第二套恢复操作。按钮无障碍状态描述与可见状态一致。

## 验证边界

本轮验证针对专用 API36 ARM64 模拟器及自有页面，包含断开／重连、前后台切换、屏幕电源、SQLite 宿主边界和横竖屏控件。未把它当作游戏身份、领取资格、真机当前构建、留出主题或长期运行的证明。实际输入用例只作用于自有夹具；没有游戏领取／消费、通知发送或 Release。
