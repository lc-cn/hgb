# 区域关联与图形状态离线实验

2026-11-18，基于 `06312eb`。用户批准对已有私人截图做离线识别实验；不操作游戏、不发送输入、不发布 Release。生产 `app` 与 `vision` 源码、模型和阈值均未改动；新增能力只在 `maaprobe` 探针内。

## 做了什么

- `maaprobe` 新增独立 JNI 库 `yys_maa_region_probe`：同一 MaaFramework 5.16.1 会话，按调用传入 `OCR`／`TemplateMatch`／`ColorMatch` 与明确 ROI；模板经 `MaaResourceOverrideImage` 从内存注入，无控制器、无动作、无流水线图。
- `tools/qa/prepare_region_experiment.py` 按 SHA-256 核对5张私人帧，复制到忽略目录并生成只含几何的 spec；模板在设备上从指定帧裁出，不另存派生图片。
- `MaaRegionStateExperimentTest` 默认跳过，仅在 `-PincludePrivateRegionExperiment=true` 构建并传 `-e includePrivateRegionExperiment true` 时运行。只断言传输状态、算法身份和结果框在 ROI 内，不断言业务阈值；每个用例重复3次。
- 两个模板：魂玉图标（取自领取后列表的每日礼包按钮）、“已领取”红章（取自已领详情第一列）。在同一帧同一位置上的用例标为 circular，不计入可分性。

完整指标见 [verification.json](verification.json)；其中不含图片、OCR 原始文字、账号值或设备序列号。

## 环境结果

| 环境 | 结果 |
| --- | --- |
| 专用 API36 模拟器 `yys-assist-dev` | **首个 TemplateMatch 即进程崩溃**：SIGILL 位于 OpenCV KleidiCV `sve2::float_conversion`（由 `cv::matchTemplate` 调用）。宿主为 Apple M5，guest `/proc/cpuinfo` 列出 `sve2` 却没有 `sve`。API30 AVD 同样列出 `sve2`，未运行。此次没有记录任何测量 |
| 真机 SM-G9910／API35 | CPU 特性不含 SVE，1项测试 OK，全部用例三次重复结果一致 |

模拟器崩溃说明：只要使用 Maa 模板匹配，就不能把 Apple Silicon 宿主上的 AVD 当成可用测试环境；这不是真机或 Windows 模拟器的结论。OCR 路径此前在同一 AVD 正常，本次只在模板匹配时触发。生产中若加入模板匹配，必须仍放在现有隔离识别子进程，崩溃只能按“观察失败”处理。

## 真机测量

**样本独立性先说明**：三张列表帧在全部8张卡片的按钮和图片 ROI 内，除领取后第1张卡外**逐像素相同**（“留出”帧与领取前帧完全一致）。因此报告中的24个魂玉正例实际只有10个不同图像（7个列表按钮＋3个详情价格），负例只有2个不同图像（“领取”按钮、“免费”）。这仍是同一台设备、同一主题、同一天的数据。

| 证据 | 结果 | 可分性 |
| --- | --- | --- |
| 锚点关联：全图 OCR 找“每日礼包”／“御行达摩的赠礼” | 4帧均唯一命中；锚点框与人工框 IoU 0.69–0.81；由锚点偏移推出的 ROI 与人工 ROI IoU 0.79–0.92 | — |
| ROI 内 OCR | “领取”2/2、“免费”1/1 正确；领取后列表与详情的价格“1”在 ROI 内被读出（此前整图未检出），但同时读出图标噪声（如 `S9`、`I`）；变暗列价格“18”“30”被读成“918”“930” | 价格数字仍不可靠 |
| ROI 内魂玉模板 | 正例 0.55–0.9997（详情变暗列最低 0.55／0.59，高亮列 0.83）；负例最高 0.278 | 本组可分，变暗列裕度小 |
| “已领取”红章模板 | 唯一正例为 circular（0.999999）；27个负例最高 0.268，包括红色达摩、红包等图 | **无独立正例，不能判断** |
| 红色像素计数（RGB 下限150,0,0／上限255,90,90） | 红章列 3855；红包类卡片图分别为 8258、5643、3366；同一详情第二列红达摩 1089 | **不可分**，不能单独作为状态证据 |

## 结论与边界

1. 锚点文字＋相对偏移可以把文字与图形证据关联到同一商品／列，解决“整图有‘领取’字样但不知属于哪一项”的问题；本组未出现多锚点歧义，但没有测过歧义处理。
2. 魂玉图标的存在／缺失比价格数字 OCR 更适合区分“免费领取”和“付费”，本组可分，但样本少且裕度对变暗状态偏小。
3. 已领红章目前没有可用的独立正例；颜色计数已证明不能单独使用。需要另一天（或另一个账号／主题）的已领画面才能评估。
4. 没有跨分辨率、跨主题、Windows 模拟器或实际自动执行证据；ROI 偏移是 2400×1080 像素值。
