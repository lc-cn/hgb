# 一次免费领取与状态识别观察

2026-11-17，基于 `fec781d`。用户明确允许在网易官服当前账号的“商店→礼包屋→日常→每日礼包”完成最多一次免费领取并本地截图；不含付费、其他礼包或Release。使用人工逐帧核对后的ADB操作，不是正式助手执行器的任务闭环。

## 实际结果

开始导航后曾观察到意外进入花合战及资源显示变化，当时没有发出领取输入。停止输入并询问用户，用户确认停止操作手机后，从新画面重新核对。当前昵称／角色编号与此前资料样本视觉一致，具体值不入库；交接前的资源变化不归因于本次领取，未确定该意外页面的原因。

在当前日常列表确认“每日礼包”下为无标价的“领取”，与邻近付费礼包分开。先在本地独占写入领取意图，再仅点击该入口一次；没有因等待动画或命令返回值而重试。随后实际观察到：

1. 等待／加载层，不能当领取成功。
2. “获得奖励”窗口，显示金币30000，背景为每日礼包详情。
3. 关闭奖励层后，详情第一列“御行达摩的赠礼”出现红色“已领取”印章，底部仍写“免费”；邻列为付费项目。
4. 关闭详情后，列表同名“每日礼包”的图片及底部变化为1魂玉付费入口，不能继续按同一名称或原位置点击。

本次没有付费要求、没有点击任何价格／充值／兑换按钮，没有再次领取；经商店地图返回庭院。奖励层内空白点击没有关闭提示，随后点击弹窗外空白才关闭；此类关闭不能通过固定延迟或点击次数猜测完成。取得奖励与已领取状态均由实际画面核对，没有用退出码替代业务结果，也没有向助手运行历史补写虚构执行记录。

原始画面、角色资料、资源余额、导航／领取意图及完整OCR均只保存在忽略目录。提交的[verification.json](verification.json)只含脱敏观察、帧与标注摘要、固定模型、实际安装产物及识别指标；没有图片、账号值或设备序列号。

## 固定离线模型对照

在专用API36 ARM64模拟器中，用既有无网络／无控制器探针、固定MaaFramework 5.16.1与转换后的PP-OCRv6 small处理本轮四张原始真机帧。生产源码、模型及阈值未改；手机未安装探针。对同图整图与人工选定区域分别重复三次，结果一致：

| 帧及人工标注 | 整图命中 | 局部区域命中 |
| --- | --- | --- |
| 领取前列表：每日礼包、领取 | 2/2 | 2/2 |
| 奖励层：每日礼包、获得奖励、30000 | 3/3 | 3/3 |
| 已领取详情：每日礼包、御行达摩的赠礼、已领取、免费 | 2/4 | 3/4 |
| 领取后列表：每日礼包、1 | 1/2 | 1/2 |

指标沿用忽略空白、文字一致且框有交集的一对一匹配。四张原图共有11处标注，包含8种公共文字；区域和重复不增加独立样本，不计算完整精确率。标注没有独立复核，没有留出主题。

关键失败保留：**“已领取”整图被识别成“領取”，局部区域被识别成“领取”，均未正确命中完整状态词。** 对应置信读数约0.766和0.828；不得据此把后者当成可领按钮，也不采用繁简／字符替换把失败改成成功。付费入口数字“1”在整图及局部均未检出，不能把“未识别到价格”解释为免费。局部输入改善了详情标题，但没有解决状态红章或价格判断。

[ocr-test.txt](ocr-test.txt)的一次instrumentation用例通过，仅证明既有协议断言、模型字节、无网络／无控制器及输出读取成立；用例本身不要求所有人工标注命中，上表明确保留失败。

## 对任务制作的影响

现有 `screen.readText`／`screen.classifyText`／`screen.locateText` 只按文字证据工作；分类不理解按钮、印章或货币图标，也没有前景层级／商品行关联。单纯将“领取”配置为ready、未命中已领配置为done，或者沿用旧坐标，都不能满足这组实际页面的约束。

下一步需验证可关联目标区域与文字之外的状态／货币证据，再决定通用动作合同及任务资源表达；这是识别能力与任务适配的缺口，不能靠队列状态机或为这个游戏硬编码分支补偿。当前没有生成可运行的每日礼包任务，未因一次人工领取或静态探针通过而宣布M3／M4完成。
