# 游戏内返回键观察与每日礼包状态

2026-11-18，基于 `6edb63c`，SM-G9910／API35，官服客户端 2.8.88／引擎 2.8.89。用户批准游戏内验证；本轮不领取、不购买、不下载。操作为人工逐帧核对的 ADB 输入，不是正式 App 执行器。私人截图与导航记录只保存在忽略目录。

## 观察

1. 启动游戏，进入庭院，打开菜单进入商店，商店弹出“式神模型扩展包下载（5278MB）”对话框。
2. 在该对话框上发送一次系统返回键（`KEYCODE_BACK`，系统层与无障碍 `GLOBAL_ACTION_BACK` 相同的按键事件）。**游戏没有关闭这个对话框，而是弹出系统风格的“确定退出阴阳师？”（取消／退出）。**
3. 点击“取消”后回到下载对话框；再点击下载对话框的“取消”，进入商店。没有再次发送返回键。
4. 进入礼包屋 → 日常：每日礼包卡片按钮再次显示“领取”，说明 11-17 领取后已刷新为可领取。按钮区域与 11-17 领取前截图逐像素相同；卡片图片区不同（倒计时文字由 47 天变为 46 天）。本帧 SHA-256 `0c806260d2a314492c6324cda36d4d1d7e446009aceece141ca4f222831c5d74`。

## 结论

- 在本游戏中，**系统返回键不会关闭游戏内弹窗**：至少在这个对话框上，它会触发游戏的退出确认。若在退出确认上再按一次返回键或误点“退出”，就有退出游戏的风险。`screen.back` 不能用来关闭奖励弹窗或其他游戏内对话框；任务作者不应在游戏界面使用它，除非已在具体画面上观察过它的效果。
- 关闭奖励弹窗仍需要“点击弹窗外空白处”一类的输入，现有动作还不支持（点击只针对识别到的文字目标）。
- 这只是一个对话框上的单次观察，没有覆盖其他弹窗。

今日每日礼包为可领取，本轮没有领取。游戏停留在礼包屋日常列表。

## 领取尝试中止（未发生输入）

用户批准用助手正式动作链领取一次今日免费礼包。尝试以真机 instrumentation 运行真实执行器：`am instrument` 会重启助手进程，系统随后把助手的无障碍服务列为 “Crashed services”，且未自动重新绑定。测试等待服务连接 30 秒后超时，**没有观察、没有动作意图、没有点击**；领取前后截图一致，按钮仍为“领取”。

结论：
- 在真机上，instrumentation 结束助手进程后，无障碍服务进入崩溃状态，需要用户在系统设置中手动关闭再开启。随后的一次 `adb install -r` 覆盖安装后，服务由系统自动重新绑定，没有进入崩溃状态；
- instrumentation 不能用来在真机上驱动正式执行器。

本轮没有修改系统无障碍设置。

## 经调试触发入口的正式领取（2026-11-18）

用户在系统设置中重新开启了无障碍服务，并改为在调试构建中加入只有 adb 能触发的入口 `LocalTaskTrigger`（`android.permission.DUMP` 保护，仅 debug 变体）。该入口在已运行的助手进程内，用独立的临时数据库和资源目录安装本地任务包，经真实 `ExecutionRuntime`、持久化、无障碍桥和识别子进程执行一次任务，结果写回应用外部文件目录，结束后删除临时数据库。用户的正式版本库、配置和队列都不受影响。

- 安装带入口的构建后，无障碍服务仍为绑定状态；游戏切回前台后落在商店地图，人工点击进入礼包屋 → 日常，确认按钮为“领取”。
- **领取运行**：观察 → 定位“每日礼包” → 推出区域 → 判为可领取 → 在整图定位“领取” → 写入意图后点击一次（平台完成回调）→ 等待 2.5 秒 → 重新观察并核对“获得奖励” → 任务完成。只有 1 条设备动作，即这次点击，没有重试；从触发到结束约 12 秒。
- 奖励弹窗显示一项道具奖励（与 11-17 的金币不同）。人工点击弹窗外空白处一次后，详情第一列出现“已领取”红章，这是第二天的红章样本，背景奖励与 11-17 不同；再点击外部空白处一次，回到列表。全程没有点击任何价格按钮。
- 列表中每日礼包变为 6 魂玉付费入口（11-17 为 1 魂玉），按钮像素与 11-17 的付费帧不同。**对这一从未参与适配的付费状态再运行一次任务**：判为付费，核对列表后完成，没有任何设备动作，画面前后按钮区域逐像素一致。
- 手机上暂存的任务包、模型和模板，以及触发结果均已删除；私人截图、结果与导航记录只保存在忽略目录。

局限：只覆盖同一设备、同一主题、两天的样本；魂玉模板阈值 0.45 仍为暂定值；关闭奖励弹窗与详情仍由人工 ADB 点击完成，助手还没有对应动作；导航到礼包页也不在任务内。
