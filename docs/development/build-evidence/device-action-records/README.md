2026-11-17。合同与使用责任见[执行持久化](../../execution-persistence.md)。本轮是已批准输入链路的必要记录能力，不声称在旧源码上执行了依赖新 API 的测试。

- `build.txt`／`core-build.txt`／`integration-build.txt`：最终源码核心 90 项通过、debug 主／测试 APK 和 Lint 通过。分开的日志保留实际执行与 up-to-date 状态，不把后续缓存构建当作额外重跑。
- `android-full-tests.txt`：专用 API36 ARM64 模拟器完整 128 项中 126 通过、2 条件跳过；两个分阶段进程测试分别在 `process-seed.txt`、`process-verify.txt` 通过，中间真实强停。该进程测试是既有无输入工作器，不证明真实游戏输入被杀后的核对。
- `android-boundary-tests.txt`：32 项通过，与完整批次重叠。新增实际 SQLite 提交门、提交前注入失败、提交后丢回执只读确认、带输入记录的宿主重建及保留版本引用。故障是受控异常，不是实际磁盘事故；宿主重建不是 Android 进程终止。
- 自有画面的真实平台输入用例通过：意图事务被挡住时零触摸，提交后只产生一次触摸；平台完成回执入库，业务仍未确认。暂停后保留未知及版本引用。真实手势由测试工作器发出，不是已注册的 JSON 点击能力。
- 核心用例验证准备态隔离、同 ID 重投不产生第二次新许可、改内容及冲突回执拒绝、迟到回执归旧尝试、未知／移除语义、旧格式缺字段兼容，以及错误归属和重复 ID 的反序列化拒绝。没有保存动作游标。
- `installed-artifacts.json`／`verification.json`：模拟器主／测试包和真机主包均与被测构建摘要一致。主包没有模型或游戏任务夹具；只按明确选项给测试 APK 携带模型。源码摘要用于核对本次证据范围，没有修改依赖、Manifest 或 Room schema。
- `phone-check.json`：用户在 SM-G9910／API35 手动授权后，正式 App 页面显示已授权，截图检查实际取得 1080 × 2400 可读画面；另以 ADB 确认官服庭院并看到助手浮层。前者是助手画面检查，后者不冒充 App 游戏 OCR／输入结果。账号图、序列号和登录态不在提交材料内。
