# 动作参数与前序输出引用

2026-11-16。M2 内部合同增量：同一任务定义可读取已锁定的用户配置，并引用同一步骤前序动作的输出。沿用现有 `StepDefinition.actions` 和唯一执行器，不增加动作暂停状态机或脚本引擎。观察／输入／业务验证动作、分支／循环仍需继续实现，完整任务语言尚未冻结。

## JSON 表达

`inputs` 继续放常量，新增可省略的 `bindings` 放按参数名声明的结构化引用：

```json
[
  {
    "id": "first",
    "capability": "control.wait",
    "contractVersion": 1,
    "inputs": {},
    "bindings": {
      "durationMs": {"type": "configuration", "fieldId": "milliseconds"}
    }
  },
  {
    "id": "second",
    "capability": "control.wait",
    "contractVersion": 1,
    "inputs": {},
    "bindings": {
      "durationMs": {"type": "output", "actionId": "first", "field": "durationMs"}
    }
  }
]
```

这段是动作列表。完整可解析夹具见 [task-bundle-bindings.json](../../core/engine/src/test/resources/task-bundle-bindings.json)，只作为测试资源，不进入主 APK、正式任务库或 Release。它表达两次等待，不是游戏领取。

配置引用只能读当前任务 schema 中明确必填的字段，实际值取本轮 `TaskSnapshot.configurationJson`。这是首版无条件动作列表的合同：不会把缺失值替换成零、空串或任务作者未声明的默认。类型或值不兼容时明确拒绝，用户不需要写引用表达式；制作器未来可按声明生成选择项。

输出引用只能指向本步骤较早动作已声明的一个顶层输出字段，不支持自引用、未来引用、跨步骤／任务、动态属性路径或字符串插值。前一步骤完成不意味着其临时输出会被带到下次恢复；需要的游戏事实仍应在本步骤入口重新观察。

`formatVersion` 仍为当前内部版本 1。旧任务没有引用时省略空 `bindings`，保持原序列化形态；不重写已缓存的旧内容或摘要。旧容器的严格未知字段校验会拒绝带 `bindings` 的新任务，不会忽略引用后误执行。

## 合同与数据所有者

APK 的 `CapabilityContract` 声明可引用参数及输出字段的 JSON 顶层类型。当前类型为 STRING／NUMBER／BOOLEAN／OBJECT／ARRAY；对象与数组的业务结构由具体动作校验，不声称这是完整 JSON Schema。参数声明当前均为必需参数。任务包不能自行注册能力或输出类型。

- 装载：核对动作及合同版本、参数来源唯一性、字段存在、前序关系和类型；同一参数不能同时给常量与引用。
- 保存与入队：版本库复用同一 `BundleCodec.configurationIssues`，先验证 schema，再验证可由配置／常量确定的动作参数。配置保存、候选读取及最终状态事务都使用此入口，不能绕过保存直接提交坏参数。
- 执行：按顺序解析输入，检查实际参数，动作成功返回后检查输出字段与类型，再交给后续动作。依赖输出的实际值在运行时校验，保存时不伪造输出或猜测动作结果。
- 恢复：输出表只在一次 `execute()` 中存在。未完成步骤重入从第一个动作开始，输出重新取得；完成步骤进度及人工暂停仍归原执行器管理。

用户修改已保存配置不修改在途快照，任务版本与排序规则同样保持原锁定行为。没有改动 Room schema 或恢复／失败／未知的处理规则。

## 首个实际动作

`control.wait` v1 仍是唯一正式登记的动作，输入 `durationMs`，输出同名数值字段；该输出表示已经完成的请求等待时长，不是精确墙钟计时或业务成功证明。不会用输出字段名注册更多动作。

等待时长按十进制精确转换到非负 64 位整数毫秒：`12`、`12.00`、`1.2e1` 含义相同；字符串 `"12"`、非整数、负数或超界值拒绝。不经 Double，不截断、不夹取、不偷偷改用户输入。配置保存仍保留原数值表达，解释器只为执行取得精确整数。

原实现按数字文本的 `longOrNull` 处理，导致 schema 接受的 `12.00` 被动作拒绝。新增测试先复现该合同冲突，修复在等待动作的精确数值读取处；没有放宽小数或溢出断言。

验证证据见 [action-bindings](build-evidence/action-bindings/README.md)。核心测试包括完整手写 JSON 经真实等待解释器运行、前序关系／类型、缺值、实际虚拟时长、取消重入和精确数字；Android 使用独立 Room 库验证保存、候选及最终入队事务和实际宿主锁定参数。没有在游戏或正式任务目录安装夹具。

## 尚未覆盖

这不是完整任务 DSL，也没有把 OCR 输出接到设备输入。条件／循环、业务完成判据、未知副作用核对、观察定位的数据与帧身份绑定、GitHub 私有源授权及代表领取继续推进。现有观察 API 与 native 进程代码本轮未修改；不拿等待样例或绿色测试代替游戏与留出主题验证。
