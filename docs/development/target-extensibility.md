# 多目标应用的扩展边界

用户于 2026-11-16 明确：后续除阴阳师外，还可能支持其他游戏或普通 App。首期闭环仍以阴阳师验证，不新增多应用切换页面或跨应用自动调度规则。

## 内容与运行时各自负责什么

| 所属 | 职责 |
| --- | --- |
| Android 容器 | 提供受版本约束的基础动作、截图／输入适配、唯一执行器、任务版本与配置管理、记录和通知基础设施 |
| 目标应用内容 | 声明稳定 `targetId`、显示名称、支持包名、身份要求和任务分类；提供该应用的任务步骤、schema、识别资源与场景定义 |
| 目标专用适配 | 需要时负责身份核对、启动／关闭及登录态等平台能力；普通 App 不被要求提供游戏区服或登录态快照 |
| 用户计划 | 引用目标内的任务及配置，并保存对应执行身份；不会通过名称相同把其他应用的任务或账号混在一起 |

新增目标如果只依赖已有动作合同，可以随任务内容发布；需要新的基础能力时，仍须更新 APK。目标描述不具有注册原生能力、运行任意代码或放宽设备输入权限的能力。

## 已加入首版核心的合同

- 任务集包含 `targets`；每个任务显式声明 `targetId`，分类属于对应目标。任务身份为 `(targetId, taskId)`，不同目标允许使用相同局部 ID。
- 执行请求、运行事实与当前上下文携带 `ExecutionContext(targetId, principal)`。后续配置、计划、持久记录及引用索引也必须保存该命名空间，不能只按局部 ID 建表。
- `principal` 为明确的账号身份或 `Anonymous`。`null` 上下文表示尚未核对；无需账号的 App 使用明确的匿名身份，两者不能互相代替。
- 目标身份策略为无需账号、账号可选或必须有账号。内容校验与执行上下文核对分别进行；满足身份策略不等于已确认前台包名，更不等于获得输入权。
- 执行器只选择与当前已核对上下文完全匹配的请求。单例执行器及输入所有权仍是共享边界，不为每个目标各起一套竞争输入的调度器。
- 已确认的同应用换号语义保持：静默且无未决结果后，实际换号清空原队列并保持暂停。已有其他目标的未结束工作时，核心返回明确的待处理结果，不借换号默默删除它们。

这些是未发布数据合同的首版实现；本地测试使用虚构目标和包名，不能作为实际支持其他 App 的声明。尚未发布任务 JSON，因此本次没有线上数据迁移或版本兼容承诺。

## 后续实现必须延续的边界

工作台的游戏资料、任务分类和目标标识应从目标内容／适配结果读取。资源不足、御魂、区服等词和规则留在阴阳师任务与适配层；通用执行器不依据这些业务概念分支。云视觉也应收到目标及当前任务所需上下文，而非内置一份全局阴阳师提示词。

多应用选择方式、跨应用计划、切换时如何处置队列、并发和多设备均未确定。这些产品行为进入实现前另行确认；当前只提供隔离与合同边界，不自动启动或切换到其他 App。

## 当前验证

核心集成测试覆盖跨目标同名任务分别入队、未核对身份不能执行匿名任务、匿名目标可正常执行，以及切换目标不会悄悄丢弃未结束工作。内容合同测试覆盖跨目标局部 ID、目标分类归属与身份策略。Android 原生界面和真实游戏兼容性分别验证，不由上述测试推导。
