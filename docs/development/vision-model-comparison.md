# 离线 OCR：tiny 与 small 的同轮对照

2026-11-16。官方较大的 PP-OCRv6 small 在当前菜单及庭院局部上优于 tiny，但仍有漏检，**未冻结生产后端，未执行游戏任务**。这是首轮[离线识别实验](offline-vision-probe.md)的后续；原来的 tiny 失败指标未删除或改成通过。

## 实验约束与可复现性

两套模型使用同一份固定 Paddle SDK、OpenCV4.11.0／ORT1.21.1、默认检测／识别参数、同一 API36 ARM64 AVD 和无网络权限探针。模型入口来自[固定官方 Android 文档](https://github.com/PaddlePaddle/PaddleOCR/blob/dab3fe35379033fdcb2d0e9572fac0b36c9a9ebf/docs/version3.x/inference_deployment/cross_platform/android_deployment.md)。其列有 small、tiny 及官方 ONNX 下载；这说明候选来源，不是本项目精度证据。

先运行 tiny，再运行 small，每套启动前清理独立探针数据；每张图各重复三次。两个最终测试 APK 字节相同，所含私有输入逐文件摘要也相同。另核验目标 APK 内实际 ONNX／字典字节与各自锁文件相符，且打包的模型清单等于设备结果中的清单，避免只核对源码目录却测试了旧模型。

模型来源、归档及逐文件摘要固定在 `visionprobe/models.lock.json`；这些摘要是本次取得并复算的基线，不冒充上游签名。生成目录和构建参数按版本分开，默认仍为 tiny；切到 small 不覆盖 tiny 的生成文件。构建校验同时检查变体身份、来源、文件清单、字节数和摘要，不接受多余模型文件。错误变体声明及改动一个模型字节均实际被拒绝，恢复后校验通过。Gradle 配置缓存仍开启，脚本对象捕获错误在任务边界修复，没有禁用缓存。

## 样本与指标

除原有的合成浅色、深色和空白图，还使用此前只读取得的三个局部：商店底栏、庭院底栏、商品名及价格。后两块在本轮按原图目视标注，未由用户独立复核。原始画面、局部选择及私人诊断只留忽略目录；没有上传识别、调用游戏或保存真实账号／余额到可分享结果。

下表为**文字完全一致且与对应标签框有交集的一对一匹配**。原来的全图文字严格匹配及 bestIoU 继续保留；新指标按 IoU 降序分配，每个 OCR 结果至多匹配一个标签。匹配仅要求正交集，没有把它设为生产点击的定位阈值，也不声称是复杂重叠标签的全局最优分配。两个相同价格不能共用一个结果；单个大框覆盖两个价格也只能算一次，已有独立断言。

## 代价与验证边界

打包模型文件（含字典）tiny 为 6,298,800 字节，small 为 31,190,469 字节，约 4.95 倍。当前 APK 含上游多 ABI native 库，且使用增量打包，不从本轮 APK 文件大小推导正式部署体积。

这次 tiny／small 创建耗时约 94／201 ms，Paddle 运行后进程 PSS 点值约 191／256 MiB；包含模型、SDK、运行时及进程状态，不是引擎独立峰值。样本与重复数很少，执行顺序固定，不能据此做真机耗时、热状态、内存泄漏或速度排行结论。完整逐次数据在[证据目录](build-evidence/vision-model-comparison/README.md)。

两套变体分别通过同一组 2 项仪器用例：本地识别集成与重复数字位置匹配。不是 4 项不同业务测试。探针 Lint 仍为 0 错误、4 条既有告警；OpenCV4.11 的16 KB对齐限制未被压制，仍只是实验组合。

正式 App 没有新增模型或依赖。在两套探针模型目录都暂时不存在时，`:core:test :app:assembleDebug :app:lintDebug` 通过，正式 APK SHA-256 与已验证的悬浮阶段完全相同；不是用本轮探针测试冒充正式 App 的游戏能力。

## 下一步

保留 small 为较强的实验候选，继续 Maa／native兼容性、资源生命周期及真正留出主题对照。推进领取任务时，需要当前场景、资格、目标唯一性和执行后结果的独立观察，不能凭“商店”二字识别成功就开始点击。当前真机未连接，已有截图是历史只读证据，不能证明此刻的登录态或领取状态。
