# 执行状态与版本引用的持久化边界

2026-11-16 开始接入，2026-11-17 补充必要输入记录及屏幕动作。正式 Application 使用唯一 ExecutionRuntime、真实 SQLite 状态存储与任务版本引用。已注册等待、文字观察、定位、点击及核对动作；实际游戏闭环尚未完成，存储测试不等于游戏自动化通过。

## 准备、落库、发布

现有 `TaskExecutor` 的直接命令会立即更新状态。新增 `prepare(command)` 在不发布的状态副本上使用同一套调度规则计算下一状态、回执与 effects。它不创建工作器，不发送输入。`commit(prepared)` 检查来源和修订后发布；过期、异主或重复提交会报错。

宿主必须独占命令入口：准备 → `ExecutionStateStore.persist` → 核心提交 → 投递 effects。不能把 effects 交给页面自行消费，也不能让 UI 协程取消丢掉已经接受的命令。数据库提交结果不确定时，需要核对已存修订；不能将它当作失败换 commandId 重投。当前宿主独占该路径，提交回执丢失时只读核对修订与完整状态；只有确认原写已提交才发布状态和 effects，不盲目重写。宿主与 SQLite 集成测试覆盖调用方取消和提交确认丢失，真实设备输入的持久化交接仍需验证。

存储事务同时处理状态 JSON、摘要、修订和 `executor-run/` 命名空间的版本引用：

- 新轮次核对当前启用版本、目标身份策略、真实任务定义、已保存配置及 schema 有效性，避免提交间隙切版本／改规则造成串用。
- 在途、排队、人工暂停和未决结果继续保留对应版本引用；安全结束释放本模块引用，其他持有者不受影响。引用 reason 是锁的用途，工作状态仍由 Executor 投影。
- 修订或基状态不符拒绝写入；损坏记录报错并保留数据。状态行缺失但仍有执行引用时，不冒充首次启动，不清引用。
- 反序列化只重建记录，不产生工作器启动，也不证明旧输入已结束。

## 删除内容后的迟到未知结果

已完成轮次通常不再锁住内容，用户可以删除历史版本。核心既有合同要求迟到未知结果仍阻塞新输入。原实现删除版本整行后，存储层会因为找不到版本而拒绝保存这条未知证据；新增真实 SQLite 测试取得了明确失败。

修复位于版本库的内容／身份生命周期：删除清掉 JSON 并从本地版本列表移除，保留版本号、摘要和发布元数据。未知结果可以引用这一身份，不恢复任务内容，也不能用缺失内容运行任务。原外键保护保留；同版本重新获取仍核对原摘要，内容替换被拒绝。重新取得原内容后，未决引用继续保护它，核对结果后才释放。

该变化没有增加普通界面的行或说明。缓存附件尚未实现，当前清理的是 JSON；后续资源文件也必须遵守同一引用规则。按历史 tag 重新获取原内容的传输接口仍未实现，不能宣称删除后的任务已可自行恢复执行。

## 状态格式与规模验证

格式 2 按轮保存运行定义，每次尝试只记录步骤位置和尝试身份；未决证据引用原尝试，避免每一步重复序列化整个计划。命令回执仍保存请求以核对幂等重投。格式 1 的真实旧实现生成 fixture 保留在测试资源中，验证升级后暂停交接、未知、步骤进度和代际不丢失。没有保存动作中途游标或工作器调用现场。

同一个开发基准：40 个任务、每任务 20 步、每任务约 4 KiB 配置，完成 100 步：

| JSON 大小 | 原格式 | 格式 2 |
| --- | ---: | ---: |
| 初始 | 704,661 B | 352,817 B |
| 完成 100 步后 | 18,380,924 B | 439,280 B |

基准是本机单次、未预热 JVM 测量，只比较所选合成数据的大小，不作为 Android 延迟或 24 小时运行结论。修复前后原始输出、源码／APK 摘要在证据目录。另有最终实现上的规模回归测试；未在旧源码上回放该新增 JUnit 用例，修复前比较来自同一独立基准。历史和回执仍随使用线性增长，长期存储、分页及留存策略尚未验证或定默认。

## 证据与剩余工作

`build-evidence/execution-store/`：55 项核心测试、47 项 Android 测试（9 项执行存储、9 项版本库，以及原平台桥／配置／来源／UI 场景）通过，APK 构建和 Lint 通过。新增 SQLite 场景覆盖真实数据库重开、配置变化回滚、并发修订、未知与移除、引用隔离、内容删除后的迟到结果、腐损和 1→4／2→4 迁移链。迁移 3→4 保留现有表并为旧版本行添加缓存标志；没有破坏性重建回退。

用户已确认 App 重新打开后自动恢复可确认安全的任务，未知保持核对；原人工暂停继续保留。当前宿主用原锁定版本和 APK 工作器检查步骤是否完全不涉及设备输入；符合时从未完成步骤入口重入，保留已完成步骤。缺少证明则持久记录未知，不直接重放。实际进程强停验证及其限定见下面的宿主集成记录；尚无掉电、游戏任务、离线识别、三层悬浮、Windows 或长时运行完成证据。

## 运行宿主与原生控制集成

Application 只创建一个宿主，任务行提交入队命令；工作台和历史订阅同一快照。读取中与读取失败不显示为空队列。任务行的暂停／停止／恢复命令携带所显示轮次的 runId，旧页面的手势不能误操作下一轮。排队项禁用重复提交，工作台右滑移除复用核心的撤销／静默交接。

上下文核对在独立 IO 工作中执行，避免慢查询阻塞暂停命令；同一尝试重新核对时，仅接受最新核对 Job 的结果。新增设备回归在修复前复现旧成功结果覆盖新核对失败、误启动工作器；修复只在绑定结果的所属检查处拒绝过期回复，不增加第二套调度规则。

进程恢复验证用两次显式选择的 instrumentation，中间 adb force-stop，在同一隔离模拟器的专用 QA 数据库调用生产宿主和实际等待工作器：核对进程 PID 改变、尝试 generation 增加、完成步骤不重做、原队列保留。没有向主 App 数据库注入演示任务，没有操作游戏。它不证明含输入或业务副作用任务的恢复。证据和最终构建摘要见 `build-evidence/runtime-host/`。

## 提交等待期间的输入所有权

宿主的输入许可是唯一执行器状态的票据投影。准备下一状态后，若旧票据不再获准，立即收回其输入许可；此时旧的持久／UI 状态保留，新工作器不启动。写入成功并提交核心后才能发布新的许可。被明确拒绝、已回滚的事务只恢复原提交状态的许可；未确认的写入不会重开输入。

这解决慢 SQLite 在暂停／停止／移除／抢占时留下的输入窗口，不改变队列规则，也不等同撤销已经被 Android 接受的手势。自有触摸界面的修复前失败与修复后证据、提交失败和拒绝抢占用例见 `build-evidence/device-runtime/`。业务副作用日志仍待实际输入动作与结果观察共同接入。

自审发现已有执行记录所引用的版本身份损坏，被归为普通 ExecutionStateRejected，可能在回滚后重新开放原输入。存储层现将旧轮次身份缺失、损坏或绑定冲突归为 CorruptExecutionState，进入宿主故障路径；新入队的配置／内容不符仍是普通拒绝，保留原任务执行。新增真实 SQLite／宿主回归先失败后通过，不清理损坏原数据。

## 必要输入记录

输入适配器须先经同一宿主提交 `RecordDeviceAction`，确认实际持久化的新 `Recorded` 回执，之后才可向原设备桥请求输入。记录包含唯一调用 ID、步骤尝试票据、任务内动作 ID、APK 能力／合同版本、观察引用及记录时间；观察引用只是同次观察的关联身份，不是截图、坐标、账号认证或画面新鲜度证明。

相同调用 ID 与完全相同内容重投只返回 `AlreadyRecorded`，不能据此再次发送输入；同 ID 改内容会被拒绝。记录成功不新建输入会话或重新授权，投递时仍须经过原设备桥的票据、前台、方向和授权代次检查。暂停交接后不能登记新输入，旧调用的重复回执也不能重开许可。记录写入失败沿既有存储故障路径关闭许可；提交回执丢失仍先只读核对已存修订，不盲目重写或发送第二次。

`RecordDeviceActionReceipt` 只接收平台投递事实：确认未发送、平台完成、平台取消或未确认。平台完成不是业务成功，取消不意味着没有任何触摸生效；业务结果仍属于后续观察与 `StepOutcome`。迟到回执归原尝试，不推进新步骤，不清除未知、不复活已移除项。完全相同回执幂等，冲突证据保留原记录并明确拒绝，不静默覆盖。

记录挂在原尝试下，随现有状态／摘要／修订及版本引用事务保存，没有另建调度器或动作暂停状态机，也没有动作恢复游标。历史输入与该步骤结果分开保留。重新打开或安全重入时，APK 无输入证明还须与记录一致：待回执、平台完成、取消及未确认记录都不能当作“从未发送输入”；仅输入所有者明确记录未发送的调用不构成此矛盾。核对未知、手动暂停及版本引用规则保持原义。

格式 1／2 的旧尝试没有新字段时按空记录读取；无记录时不编码此字段，Room 表与 schema 版本不变。带新记录的状态需要认识新字段的 APK；没有证明旧 APK 能降级读取它，不能通过清理记录来强行降级。这与用户选择云任务旧版本的功能不同。

该基础检查点 90 项核心测试、完整 Android 128 项中 126 通过／2 条件跳过，两个实际进程强停／恢复阶段另行通过。32 项定向测试与完整批次重叠；其中实际手势测试使用独立库和自有模拟器画面，验证意图提交前零触摸、提交后一次触摸、平台完成回执落库但业务仍未知。存储异常注入是受控故障，不是设备磁盘损坏；带输入记录的恢复检查来自宿主范围重建，不宣称已经验证真实进程被杀期间的游戏输入。证据见 `build-evidence/device-action-records/`。

此基础检查点没有注册点击动作或在游戏发输入。后续正式定位／点击、输入独立静默与结果核对的接入及最新验证见[屏幕定位与输入](screen-input-actions.md)。
