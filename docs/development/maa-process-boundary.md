## 采用的实验边界

`MaaObservationService` 是不导出的 bound Service，运行在 `:maa_ocr`；它与宿主同 UID，**不是权限隔离沙箱**。服务一个生命周期只接受一个观察调用，保留该调用所有权到进程结束；并发第二个调用明确拒绝，不复用前一个调用的 native 内存或停止权限。没有游戏控制器、设备输入、网络权限、自动重试或自动超时策略。

模型三件套和 PNG 通过只读 `ParcelFileDescriptor` 传输，Messenger 只承载请求 ID、长度／摘要和描述符；结果 JSON 也通过描述符返回。子进程按固定角色保存模型，独立验证传入清单的长度与 SHA-256，不把任意路径或脚本作为任务接口。摘要正确不代表 ONNX 格式有效，坏格式仍可能触发真实 native 崩溃。

主 Looper 处理停止，native 在工作线程执行。停止请求由拥有该请求 ID 的服务自行终止所在识别进程，不给调用方一个任意 PID 杀进程接口；进程名称不正确时不提供 native 服务或执行自杀。宿主不把发送停止、协程／Future 取消或解除绑定视为 foreign 使用已结束，而是等待该服务 Binder 死亡，并等待可能仍在读取结果文件的线程结束，才交付静默回调。服务未接受／宿主从未提交的调用分别有明确证据，不伪造 Binder 死亡。

宿主按同一串行 Handler 管理请求状态、死亡回调和结果交接；不会因 Android 重新连接 bound Service 而重发旧请求。系统可能短暂重建空服务，旧请求不恢复，显式新调用才可提交。结果区分有效观察、拒绝、进程死亡、取消、占用和协议错误；拒绝保留发生阶段与异常类型，不发送模型内容、文件路径或栈。正常 `hit=false` 只是一次完整观察，没有转成“目标业务不存在”。

清理失败不会阻止已经取得静默证据的使用期回调；清理错误继续向调用方报告。工作目录只在自身请求结束后清理，不删除其他调用目录。`Future.cancel` 不是这里的停止协议，实验调用方使用 `requestStop` 并等待终态；未来生产协程适配必须完成同样的交接。

结果生成与描述符交付／关闭分开：交付异常不证明结果未到达，因此不能再发送第二个“拒绝”终态。该边界来自源码自审，同一平台用例已复验，尚未注入描述符关闭故障。

## 实测结果

专用 API36 ARM64、4096 字节页模拟器，使用与上轮相同的七个上游 native 库，只有自有 JNI 新增显式调试阻塞入口。

| 情境 | 实际结果 |
| --- | --- |
| 合成文字／空白 | 两次均在不同于宿主的 PID 中识别；文字命中、空白零候选；收到死亡证据后才释放调用占用 |
| 模型摘要不符／非法图像 | 返回未取得观察，分别保留 model-copy／native-recognize 阶段及 IllegalStateException；没有改成健康空白 |
| 大于 1MiB 的有效 PNG | 添加合法 tEXt 附块后仍由 native 解码为空白，描述符路径通过，不把整个图像放入 Binder 消息 |
| 立即／重复停止 | 未提交或 Binder 死亡证据明确，占用回调仅一次 |
| 清单摘要正确的三字节 ONNX | 真实 ORT protobuf 异常导致子进程 SIGABRT；宿主 PID 保持，返回 PROCESS_DIED；随后显式新调用在新 PID 识别成功 |
| C++ 永久阻塞 | 从 JNI 内发出进入标记；此时不报告完成、不释放占用；另一调用被 BUSY 拒绝且未停止前者；停止前者后观察到 Binder 死亡才释放 |
| 实际安装元数据 | 服务不导出、声明为独立进程；主／测试包均无网络权限 |

最终显式进程批次 **7 项通过**；默认完整批次 **10 项通过、3 项跳过**（两个子进程故障和一个既有宿主终止故障需显式参数），不相加当作不同测试。原生库 ELF LOAD 和未压缩 APK 偏移仍满足 16KiB 对齐，仅在 4KiB 内核执行。准备输入移开时正式 App／core／Lint 仍构建，正式 APK 与资源版本阶段字节相同。证据见 [maa-process](build-evidence/maa-process/README.md)。

默认测试 APK 已不打包本地私有素材；比较私有素材需构建参数与运行参数同时显式选择。此轮只用合成图，没有在新进程路径里识别真实账号画面。

## 还未完成的工作

这解决的是两个已实测故障在探针中的影响范围，没有修复上游抛异常，也未冻结生产识别后端。每次观察单独启动／结束进程是实验生命周期，不是已经证明适合 24 小时工作的缓存或性能方案。控制 Looper／Binder 自身卡死、系统杀宿主、后台限制、长期泄漏及不同设备仍未实测；当前控制无法取得死亡证据时保留未结束状态，不自动释放或伪装失败。

资源版本库已经提供真实租约，但这次使用的是实验输入及静默回调，**尚未将 `TaskResourceLease` 接入 native 消费者**，也没有接唯一执行器、真实截图或任务观察动作。后续应复用经过此处验证的边界，与版本资源／观察接口统一，不能另建模型版本中心。宿主死亡的服务自结束分支有源码，尚无强停宿主实测；杀进程留下的目录也不能据此宣称跨启动清理完成。

识别进程死亡只证明该识别使用期结束，不代替设备桥的输入终态，不证明之前的游戏点击没有生效，更不确认领取／兑换／强化结果。正式 Worker 仍须保留输入与结果未知的原有约定。真实领取、留出主题和游戏完成判据继续推进。

依据：[Android bound Service](https://developer.android.com/develop/background-work/services/bound-services)、[Binder 死亡通知](https://developer.android.com/reference/android/os/IBinder.DeathRecipient)、[ParcelFileDescriptor](https://developer.android.com/reference/android/os/ParcelFileDescriptor)、[Binder 大消息限制](https://developer.android.com/reference/android/os/TransactionTooLargeException)。同时核对了本机 SDK 37 的实际公开签名，避免用 API33 的 Bundle 新重载破坏声明的 minSdk30；兼容声明不代表低版本设备已实测。
