# 步骤程序合同

2026-11-17，用户确认实施[控制流提案](../design/step-control-flow-proposal.md)后落地。任务仍由多步骤及配置 schema 组成，计划仍为任务集合与执行时间；本次没有增加动作游标、计划暂停状态或另一套执行器。

## JSON

步骤保留 `id`、`name`，选择旧 `actions` 或新 `program`，不能同时声明。旧任务仍以原形式写出；`program` 的节点由 `type` 区分：

| 节点 | 字段 | 行为 |
| --- | --- | --- |
| `action` | `action` 为已有动作定义 | 复用 APK 合同、配置／输出绑定及输入意图记录 |
| `branch` | `value` 为前序输出引用，`cases` 含 `equals` 和子 `program` | 严格同类型的字符串／布尔／精确数字比较；无唯一匹配返回 Unknown，无默认分支 |
| `repeat` | `count` 为非负 Long 范围整数，或 `{"type":"configuration","fieldId":"count"}`；子 `program` | 计次数执行；小数、字符串数字、负数、溢出和缺配置均拒绝；不默填次数 |

数值比较按十进制值，`2` 与 `2.00` 相等，`"2"` 不等于 `2`。分支比较值不能是 null、数组或对象；同值的多个 case 被拒绝。配置计数必须引用必填 NUMBER／RANGE 字段，并在配置保存和执行前再次核对整数与范围。

可直接经 BundleCodec 和原 factory 执行的完整等待夹具见 [task-bundle-program.json](../../core/engine/src/test/resources/task-bundle-program.json)；它无游戏输入、无默认配置、未发布。原[步骤片段](../design/examples/step-control-flow.proposal.json)演示状态分支和重复字段，不是完整任务集，也没有当前游戏的已领证据。

任务集格式仍为1。旧 App 的严格解码会拒绝未知 program／新动作，不能忽略分支后执行；新 App 继续接受旧 actions。任务源、版本摘要、资源及在途锁定沿用原链路，不主动迁移或改写旧 JSON。

## 装载与配置校验

`StepProgram` 共用结构遍历和控制流校验。检查全部 case 和重复块，包括零次数的定义，不以当前选择绕过不支持动作、坏引用或资源检查。分支块和每轮重复的输出只在块内可见；可以读取确定可用的外层输出，子块输出不流入共同后续，后续需要时重新观察。

校验保留每个动作前确定可用的定义和新鲜输出。任一路径上的输入都会使外层旧观察／旧目标失效；分支合流取交集。重复还检查下一轮入口，不能沿用首轮输入前的观察。校验不枚举全部路径，不按计数展开程序；只保留定义、输入后有效性及有限核对状态。

任何实际观察／输入路径必须以有效核对结束，零次或重复次数耗尽不能补出核对证据。配置保存会检查所有嵌套动作的已知参数和重复计数；装载、入队、运行继续复用相同 APK 合同。启动条件、无输入恢复证明也遍历全部嵌套动作，不能因某个分支或循环当前未执行而漏掉平台依赖。

## 状态识别动作

新增 `screen.classifyText` v1：`observation` 必须引用当前输入阶段的前序 `screen.readText`，`states` 为任务版本明确给出的数组，每项有唯一 `id`、非空 `text`、明确的 `minimumConfidence`。仅一个状态具备匹配文字证据才输出 `state`。零状态、多状态、观察失效或识别不可用分别保留 Unknown／原因，不将没找到“可领”解释成“已领”。分类结果不能替代最终业务核对。

## 执行与暂停

旧 actions 也进入同一个程序解释器；执行块只带本次尝试的局部输出，不持久化动作位置或循环轮次。每个节点和每轮重复均响应取消并让出调度，空块／零等待也不堵住撤销。

解释器把实际选中的分支和最后一轮的末尾信息传给动作会话，使最终文字核对在返回前就能留存完成证据；中间轮次的核对不能完成整步。正常走完包括尾部空块的路径时，再由解释器确认最终证据。屏幕动作不再从平铺列表的最后 ID 猜测完成位置。

人工暂停仍暂停全队；继续从未完成步骤入口重新观察和选择分支，重复也从该步骤入口重新计数。重新开始仍从当前任务首步，已完成任务保留。输入已发出而结果未知时，仍先核对，不因重新进入块而自动重放。多轮调用同一输入动作定义使用各自新的持久调用 ID，输入所有者的独立静默、平台回执与迟到证据规则保持原职责。

实际游戏领取、已领／无资格证据、留出主题与长期运行仍未验证；自有画面、静态游戏采样或构建通过均不能代替这些验收。
