# 任务版本资源与使用期保护

2026-11-16。M2 内部合同增量，沿用已有 `TaskVersionLibrary`，不新增模型版本中心。资源可随任务版本变化；App 仍只提供已实现的基础动作。

## 从 Release 到可启用版本

任务 JSON 增加可省略的 `resources`，旧的纯 JSON 版本仍可读取。每条资源包含 `id`、`assetName`、正整数字节长度 `bytes` 和小写 SHA-256 `sha256`。`assetName` 是同一 Release 的独立附件名称，不接受目录、绝对路径或下载 URL；资源 ID 和附件名称各自唯一。不同 ID 可以引用相同内容，相同摘要必须有相同长度。

示例仅说明资源字段，不是一份可执行的游戏任务：

```json
{"resources":[{"id":"ocr.det","assetName":"det.onnx","bytes":9893172,"sha256":"<该附件的64位小写SHA-256>"}]}
```

拉取仍从指定仓库的 latest 正式 Release 读取 `task-bundle.json`。资源按该 Release 返回的 asset ID 下载，附件必须唯一、uploaded，GitHub 的长度和摘要须与任务清单一致。没有从任务内容发起任意地址请求的接口。直接响应和重定向继续使用同一注入的 HTTP 客户端；私有仓库授权和用户代理配置仍待接入，不写入开发机凭据。

资源以固定缓冲区流式写入 App 私有 `noBackupFilesDir/task-resources/staging/<随机ID>/`，传输和本地写入分别核对长度及 SHA-256，超长立即拒绝。每个资源写完后同步文件、设为只读；同文件系统原子移动到 `blobs/<SHA-256>`，同步目录后，才在原 Room 事务内登记完整 JSON 的 cached 标记。资源不会放进 SQLite、不会加载为 APK 动作或远端代码。相同摘要共用一个物理文件。

下载不持有数据库事务。取消时，HTTP Call 会请求取消，并等待回调结束、不再写暂存流，随后清理本次暂存目录。写入失败、长度／摘要不匹配、缺少附件或未知动作均不登记半个可用版本，也不替换启用选择。同版本 JSON 身份仍不可变；完整缓存再次拉取会校验本地内容并跳过资源重下。当前缺失／损坏的已缓存资源明确拒绝使用，不自动覆盖修复。

## 同一版本库的两种占用

原有持久化执行引用继续保护排队、运行、暂停和未知结果依赖的版本，不改执行器状态语义。入队锁定版本前核对资源摘要；普通目录投影只检查文件类型和长度，避免每次 UI 刷新重新哈希模型。

原生消费者通过版本库 `acquireResources(version)` 获取 `TaskResourceLease`。`descriptor(id)` 与 `file(id)` 来自同一验证清单，避免消费者重新从当前启用版本读取身份。租约核验该版本和资源摘要，只按声明 ID 提供路径，并与本轮任务相同的版本／JSON 摘要关联。消费者必须在所有 native／后台使用者达到终态之后关闭租约，不能以取消协程或移除队列项代替终态。租约未关闭时，即使原执行引用已释放，版本仍不能删除／切换；版本行占用数也包含租约，关闭后观察流立即更新。关闭幂等，关闭后的路径访问拒绝。

版本库负责从数据库线程创建到交付调用方的所有权交接；交付前取消或失败会释放尚未交付的租约。自审曾在真实 Room 线程交接复现残留 1 个占用，修复后同一断言为 0；没有在 UI 或删除路径增加绕过保护的补偿。

文件存储只有一个 Application 所有者。当前租约是同进程实际使用期保护，不持久化为第二套执行引用；进程退出后该进程的 native 使用也结束。现已在[版本文字观察](versioned-text-observation.md)接入独立识别进程：宿主保持租约直到 Binder 死亡且结果读者结束，不把协程取消当作静默。宿主自身被杀的跨进程回收仍需另测。

## 删除、回滚与中断

删除先由原事务核对启用选择、持久化引用和租约，提交内容移除后，再在后续事务核对所有剩余 cached JSON 清单，清理不再引用的 blob。新安装的文件发布、租约获取和清理使用相同数据库事务串行边界，避免下载完成但尚未登记的 blob 被并发删除。共享内容有任何其他版本／使用者时保留。删除仍保留原 JSON 摘要身份，不能用同版本名替换内容。

文件系统与 SQLite 不是分布式原子事务。文件先发布但数据库提交失败时，允许留下未引用 blob，不猜测提交结果、不删除可能已提交的内容；之后成功安装可复用，用户删除其他历史版本时会按所有剩余引用清理。删除提交失败时不会先清理文件。若提交成功但后续清理失败，错误继续向上报告，内容删除可能已生效，不报告无条件成功。

进程被杀可能留下暂存目录，暂未实现跨启动暂存清理；缺失／损坏资源不会被当作可运行内容。未进行断电实验，不声称掉电事务或所有文件系统兼容性通过。摘要检查、发布和租约获取仍可能占用版本事务；大规模任务集的延迟和内存峰值尚需设备测量，32MiB 功能用例不代表性能结论。

## 验证边界

证据见 [resource-versions](build-evidence/resource-versions/README.md)。本地 HTTP 验证附件元数据、重定向、超长／截断／错误摘要、连接断开和回调未静默时取消。Android 验证真实私有文件与 SQLite、共享删除、租约／删除竞态、数据库拒绝提交、重开、同长度字节损坏、执行未知引用、32MiB 流式资源及缓存复用；另用本地 HTTPS 从实际 `TaskUpdates` 到版本租约贯通。

以下描述资源版本检查点当时的验证边界；后续真实模型接入见[版本文字观察](versioned-text-observation.md)。这些是新增资源合同的功能及故障验证，未将旧版本不支持资源视为已复现的回归。没有发布 Release、没有正式私有源授权联调、没有加载模型或完成游戏任务。生产注册表仍仅有 `control.wait`，完整分支／循环／观察动作合同尚未冻结。Maa 探针固定 APK 模型校验尚未替换为此租约；有效摘要也不保证模型格式可推理，native 崩溃／卡死边界仍须解决。
