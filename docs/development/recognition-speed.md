# 识别提速（2026-11-18）

依据[动作证据](action-traces.md)中的 trace，在真机 SM-G9910 上用进程内回放（两天的导航截图）先量出耗时分布，再逐项处理。

## 量出的分布（改动前）

整图观察每次 2.8–4.7 秒：

- PNG 编码 0.7–1.4 秒（约 2.7MB）；子进程读取管道的时间与编码重叠；
- 原生识别 1.4–3.1 秒。

点击类动作每次 3.5–5.4 秒，原因是输入前在新截图上又做了一次整图观察。一次导航 61 秒，其中 16.5 秒是任务写定的等待。

## 改动

1. **原始像素传输。** 观察不再压缩 PNG，而是直接复制位图的 RGBA（约 10MB），通过同一个文件描述符管道传给子进程，并在协议中注明宽高。子进程在原生层把 RGBA 转成 BGR，交给 MaaFramework 的 `MaaImageBufferSetRawData`，PNG 路径保留给未声明 `rawPixels` 的后端。区域请求复用同一份像素。原生库在调试构建中也固定按 `-O2` 编译，否则逐像素转换会拖慢数百毫秒。
2. **输入前只截图，在原位置附近重新定位。** 点击、按住、滑动、区域点击和返回键在输入前只截取新画面，不做整图识别。目标改为在原位置周围的窗口内重新确认：窗口边距为目标宽高中较大者再加 160 像素，文字目标用区域 OCR，图像目标用区域模板匹配。返回键只需确认前台和画面有效。

**语义变化：** 重新定位不再检查“在整图唯一”，而是检查“在原位置附近唯一”。整图唯一性已在同一输入阶段的定位动作中确认过；目标移出窗口时，结果为无法确认，不会追着点。新增的运行时测试覆盖了“移出窗口不点击”，原有的“小幅移动后按新位置点击”测试保持通过。

## 结果（真机，同一组回放）

| 项目 | 改动前 | 改动后 |
| --- | --- | --- |
| 编码 | 0.7–1.4 s | 5–20 ms |
| 子进程读取图像 | 0.7–1.5 s | 66–102 ms |
| 整图观察 | 2.8–4.7 s | 1.9–3.3 s（基本都是原生识别） |
| 点击类动作 | 3.5–5.4 s | 0.44–1.1 s |
| 一次导航（含 16.5 s 写定等待） | 61 s | 37 s |

领取回放的行为与改动前一致：可领取起点 3 次输入后完成，付费起点无输入。

## 还能做的

整图原生识别（1.2–3 秒）现在是主要耗时，与画面中的文字数量相关（18–70 处）。后续可以考虑：
- 让任务在视觉配置或读取动作中声明只识别若干区域；
- 只在需要时才做整图识别；
- 评估检测阶段的缩放参数。

以上都要先在样本上对比准确率，再决定。
