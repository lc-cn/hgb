---

通知分两部分：**规则**决定什么时候记下一条事件；**渠道**决定把哪些规则的事件发到哪里。规则默认都关着；没有渠道订阅的事件也会记在“事件记录”里。

## 规则

| 分组 | 规则 |
| --- | --- |
| 任务 | 任务开始、任务成功、连续执行失败、结果待核对、排队等待过久 |
| 计划 | 计划开始、计划结束（可按结果筛选）、计划没执行 |
| 设备和账号 | 设备掉线、账号没切回 |
| 设备上报 | 执行无进展、运行条件中断 |

“设备上报”的两条由手机自己判断：执行无进展是同一步停留太久；运行条件中断是有任务要跑，手机却因为无障碍断开、屏幕不可用、游戏不在前台而开始不了，超过一分钟。

规则打开之后才开始记，之前发生的不会补发。同一件事只记一条。

## 渠道

| 渠道 | 要填什么 |
| --- | --- |
| 钉钉 | 群机器人的 Webhook 地址；安全设置选“加签”时填加签密钥，或者用关键词“护肝宝” |
| 企业微信 | 群机器人的 Webhook 地址 |
| Bark | 设备密钥；自建服务器再填服务器地址 |
| 邮件 | 不用填，发到你护肝宝账号已验证的邮箱 |
| Webhook | 你的地址，可带一个认证头；以 JSON 发送 |
| 本机通知 | 选一台设备，在那台手机上弹出 |

每个渠道选择订阅哪些规则。添加和编辑时可以“测试发送”，测试不会保存渠道，也不产生事件。地址、密钥保存后只显示“已填写”，不会再显示出来。

## 发送失败

渠道由服务端发送，设备掉线也能收到。发送失败会在 1、5、15 分钟后各重试一次，都失败就标为失败，可以在事件记录里点“重发”。投递结果不影响任务本身。
